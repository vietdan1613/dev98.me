Object-oriented programming (OOP) is a programming paradigm that organizes code around objects, which combine data and behavior. Python supports OOP through classes, inheritance, polymorphism, encapsulation, and other features.

This guide covers the essential OOP concepts in Python, from creating classes to using abstract base classes, dataclasses, and protocols.

### 1. Classes and Objects

A class defines the structure and behavior of a type of object. An object is an instance of a class.

```python
class Plant:
    def grow(self):
        print("The plant is growing")


plant = Plant()
plant.grow()  # The plant is growing
```

Here, `Plant` is a class, while `plant` is an object created from that class.

Classes are useful for modeling entities that have related data and behavior, such as users, products, orders, and plants.

### 2. Constructors: `__init__()` and `self`

The `__init__()` method initializes an object's attributes when an instance is created. The `self` parameter refers to the current instance.

```python
class Plant:
    def __init__(self, name, price):
        self.name = name
        self.price = price


plant = Plant("Monstera", 150000)

print(plant.name)   # Monstera
print(plant.price)  # 150000
```

When `Plant("Monstera", 150000)` is called, Python creates an instance and invokes `__init__()` to initialize it.

Technically, `__new__()` creates the instance, while `__init__()` initializes it. Most application code only needs to define `__init__()`.

`self` is a conventional parameter name, not a reserved keyword, but it should be used for instance methods.

### 3. Instance Attributes vs Class Attributes

Python classes can define both instance attributes and class attributes.

- **Instance attributes** belong to individual objects.
- **Class attributes** are defined on the class and can be shared by instances.

```python
class Plant:
    category = "Ornamental"

    def __init__(self, name):
        self.name = name


plant_a = Plant("Monstera")
plant_b = Plant("Snake Plant")

print(plant_a.name)       # Monstera
print(plant_b.name)       # Snake Plant
print(plant_a.category)   # Ornamental
```

Be careful when using mutable class attributes:

```python
class Cart:
    items = []  # Shared across instances

cart_a = Cart()
cart_b = Cart()

cart_a.items.append("Plant")

print(cart_b.items)  # ['Plant']
```

If each object needs its own list, initialize it inside `__init__()`:

```python
class Cart:
    def __init__(self):
        self.items = []
```

Assigning to `plant_a.category` creates or updates an instance attribute that shadows the class attribute; it does not automatically change the class attribute.

### 4. Inheritance and Composition

**Inheritance** allows a class to extend or specialize another class.

```python
class Plant:
    def grow(self):
        print("Growing...")


class FloweringPlant(Plant):
    def bloom(self):
        print("Producing flowers")


plant = FloweringPlant()
plant.grow()
plant.bloom()
```

`FloweringPlant` inherits the `grow()` method from `Plant`.

Use `super()` to call behavior from a parent class:

```python
class Plant:
    def __init__(self, name):
        self.name = name


class FloweringPlant(Plant):
    def __init__(self, name, flower_color):
        super().__init__(name)
        self.flower_color = flower_color
```

**Composition** builds an object by combining other objects rather than inheriting their behavior.

```python
class Soil:
    def water(self):
        print("Soil receives water")


class PlantPot:
    def __init__(self, soil):
        self.soil = soil


pot = PlantPot(Soil())
pot.soil.water()
```

Prefer composition when an object needs to use another component's functionality without representing a specialized version of that component.

### 5. Polymorphism

Polymorphism allows different objects to respond to the same operation in different ways.

Python commonly achieves this through method overriding and duck typing.

```python
class Rose:
    def grow(self):
        return "Rose is growing"


class Cactus:
    def grow(self):
        return "Cactus is growing"


def grow_plant(plant):
    print(plant.grow())


grow_plant(Rose())
grow_plant(Cactus())
```

The `grow_plant()` function does not need to know the concrete class of the object. It only needs an object that supports `grow()`.

A subclass can also override a method inherited from its parent class to provide specialized behavior.

Polymorphism makes code easier to extend because new implementations can often be introduced without modifying the functions that use them.

### 6. Encapsulation and Properties

Encapsulation groups data and behavior together and provides a controlled interface for interacting with an object.

Python uses naming conventions rather than strict access modifiers:

- `name`: public attribute.
- `_name`: conventionally intended for internal use.
- `__name`: name-mangled to reduce accidental conflicts with subclasses.

Properties allow an attribute to be accessed like a regular field while applying validation or computed behavior.

```python
class Plant:
    def __init__(self, price):
        self.price = price

    @property
    def price(self):
        return self._price

    @price.setter
    def price(self, value):
        if value < 0:
            raise ValueError("Price cannot be negative")

        self._price = value


plant = Plant(150000)
plant.price = 200000

print(plant.price)  # 200000
```

The setter ensures that a plant's price cannot be negative through this property.

Python does not enforce private attributes in the same way as languages with strict access modifiers. Encapsulation is primarily supported through conventions, properties, and deliberate API design.

### 7. Dunder Methods

Dunder methods, or double-underscore methods, let custom objects integrate with Python's built-in operations.

Common examples include:

- `__init__()`: initializes an instance.
- `__str__()`: provides a user-friendly string representation.
- `__repr__()`: provides a developer-oriented representation.
- `__eq__()`: defines equality comparisons.
- `__len__()`: supports `len()`.
- `__add__()`: supports the `+` operator.

```python
class Plant:
    def __init__(self, name, price):
        self.name = name
        self.price = price

    def __str__(self):
        return f"{self.name}: {self.price} VND"

    def __eq__(self, other):
        if not isinstance(other, Plant):
            return NotImplemented

        return self.name == other.name and self.price == other.price


plant_a = Plant("Monstera", 150000)
plant_b = Plant("Monstera", 150000)

print(plant_a)                 # Monstera: 150000 VND
print(plant_a == plant_b)      # True
```

Defining `__eq__()` can affect hashability. Python normally makes a class unhashable when it defines equality but does not provide a compatible `__hash__()` implementation.

Implement special methods when they make your objects behave naturally with Python syntax and built-in functions.

### 8. Dataclasses

Dataclasses simplify classes primarily used to store structured data. The `@dataclass` decorator can automatically generate methods such as `__init__()` and `__repr__()`.

```python
from dataclasses import dataclass

@dataclass
class Plant:
    name: str
    price: int
    in_stock: bool = True


plant = Plant("Monstera", 150000)

print(plant)
# Plant(name='Monstera', price=150000, in_stock=True)
```

Dataclasses can also generate equality comparisons by default.

Use `field(default_factory=...)` for mutable defaults:

```python
from dataclasses import dataclass, field

@dataclass
class Cart:
    items: list[str] = field(default_factory=list)


cart_a = Cart()
cart_b = Cart()

cart_a.items.append("Monstera")

print(cart_b.items)  # []
```

Each `Cart` instance receives its own list.

Dataclasses are particularly useful for configuration objects, data transfer objects, and simple domain models. They do not automatically validate type annotations at runtime.

### 9. Abstract Base Classes

Abstract base classes (ABCs) define a common interface that subclasses are expected to implement.

Python provides the `abc` module for this purpose.

```python
from abc import ABC, abstractmethod

class PaymentProcessor(ABC):
    @abstractmethod
    def pay(self, amount: float) -> bool:
        pass


class CardPayment(PaymentProcessor):
    def pay(self, amount: float) -> bool:
        print(f"Processing payment: {amount}")
        return True


processor = CardPayment()
processor.pay(100.0)
```

A class with unimplemented abstract methods cannot normally be instantiated.

ABCs are useful when you want to define a shared contract and enforce implementation of required methods at runtime.

### 10. Structural Subtyping with Protocols

Protocols provide an alternative to inheritance-based interfaces. They allow a type to satisfy a contract by implementing the required methods and attributes, without explicitly inheriting from the protocol.

Python defines protocols in the `typing` module.

```python
from typing import Protocol

class Notifier(Protocol):
    def send(self, message: str) -> None:
        ...


class EmailNotifier:
    def send(self, message: str) -> None:
        print(f"Email: {message}")


class SMSNotifier:
    def send(self, message: str) -> None:
        print(f"SMS: {message}")


def notify(notifier: Notifier, message: str) -> None:
    notifier.send(message)


notify(EmailNotifier(), "Order confirmed")
notify(SMSNotifier(), "Order shipped")
```

Both implementations satisfy the protocol because they provide the required `send()` method.

Protocols are especially useful for dependency injection, testing, and designing loosely coupled applications. They are primarily checked by static type checkers; runtime structural checks require explicit support such as `@runtime_checkable`, with limitations.

#### ABCs vs Protocols

| Feature | Abstract Base Class | Protocol |
|---|---|---|
| Main approach | Nominal subtyping | Structural subtyping |
| Explicit inheritance | Usually required | Not required |
| Main purpose | Shared contract and behavior | Describe compatible interfaces |
| Typical use | Framework base classes | Dependency injection and type checking |

### Key Takeaways

Python OOP provides several complementary tools for organizing application code:

- **Classes and objects:** Model entities with data and behavior.
- **Constructors:** Initialize instances using `__init__()` and `self`.
- **Attributes and methods:** Distinguish instance-specific state from class-level data.
- **Inheritance and composition:** Reuse behavior through specialization or collaboration.
- **Polymorphism:** Work with different implementations through a common interface.
- **Encapsulation:** Control access to internal state through conventions and properties.
- **Dunder methods:** Integrate custom objects with Python's built-in operations.
- **Dataclasses:** Reduce boilerplate for structured data.
- **Abstract base classes:** Define explicit contracts for subclasses.
- **Protocols:** Support structural typing and loosely coupled designs.

The goal of OOP is not to put everything into classes. Use the simplest design that makes responsibilities clear, behavior predictable, and code easy to maintain.
