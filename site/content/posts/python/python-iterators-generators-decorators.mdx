Iterators, generators, and decorators are powerful Python features that help developers write reusable, memory-efficient, and extensible code. They are also fundamental to understanding how libraries implement loops, data pipelines, caching, logging, and framework features.

This guide covers the iterator protocol, generator functions, generator expressions, decorators, decorators with arguments, `functools`, and lazy evaluation.

### 1. Iterables and Iterators

An **iterable** is an object that can return an iterator, usually through `iter()`. Common examples include lists, tuples, strings, dictionaries, and sets.

An **iterator** is an object that produces values one at a time through `next()`.

```python
numbers = [10, 20, 30]

iterator = iter(numbers)

print(next(iterator))  # 10
print(next(iterator))  # 20
print(next(iterator))  # 30
```

When an iterator has no more values, calling `next()` raises `StopIteration`.

A `for` loop handles this process automatically:

```python
for number in numbers:
    print(number)
```

Conceptually, Python obtains an iterator, repeatedly requests its next value, and stops when `StopIteration` is raised.

**Key takeaway:** An iterable provides values that can be iterated over, while an iterator tracks the progress of iteration.

### 2. The Iterator Protocol

Python's iterator protocol defines how custom objects participate in iteration.

An iterator implements two methods:

- `__iter__()`: returns the iterator itself.
- `__next__()`: returns the next value or raises `StopIteration` when exhausted.

You can implement a custom iterator when you need control over how values are produced.

```python
class CountUp:
    def __init__(self, limit: int):
        self.current = 1
        self.limit = limit

    def __iter__(self):
        return self

    def __next__(self):
        if self.current > self.limit:
            raise StopIteration

        value = self.current
        self.current += 1
        return value


for number in CountUp(3):
    print(number)
```

Output:

```text
1
2
3
```

Notice that the iterator stores its current position in `self.current`. Once exhausted, this particular iterator remains exhausted.

In application code, generator functions are often simpler than manually implementing the iterator protocol.

**Key takeaway:** Understanding `__iter__()` and `__next__()` helps you understand custom collections and the mechanics behind Python's `for` loops.

### 3. Generators and `yield`

A generator is a convenient way to create an iterator. A generator function uses `yield` to produce a value and suspend its execution until the next value is requested.

```python
def count_up(limit: int):
    number = 1

    while number <= limit:
        yield number
        number += 1


for number in count_up(3):
    print(number)
```

Output:

```text
1
2
3
```

Calling `count_up(3)` creates a generator object without immediately executing the function body.

When iteration begins, Python executes the function until it reaches `yield`. It returns that value and preserves the function's local state. When iteration resumes, execution continues after the previous `yield`.

A generator is useful for processing large datasets without creating a complete list in memory.

```python
def read_numbers(limit: int):
    for number in range(limit):
        yield number


for number in read_numbers(1_000_000):
    process(number)  # Assume process() handles one value.
```

This approach produces each number on demand instead of building a list containing one million elements.

**Key takeaway:** Use generators when values can be produced incrementally, especially for large datasets, file processing, and streaming workflows.

### 4. Generator Expressions

A generator expression creates a generator using concise expression syntax, similar to a list comprehension.

```python
numbers = range(1, 6)

squares = (number ** 2 for number in numbers)

print(next(squares))  # 1
print(next(squares))  # 4
```

Compare a list comprehension with a generator expression:

```python
# Builds a complete list immediately
squares_list = [number ** 2 for number in range(5)]

# Produces values on demand
squares_generator = (number ** 2 for number in range(5))
```

Generator expressions work particularly well with functions that consume iterables:

```python
total = sum(number ** 2 for number in range(1_000_000))
```

The expression produces each squared value as `sum()` requests it, rather than constructing a complete list first.

Generators are generally one-shot iterators. Once consumed, they do not automatically restart.

**Key takeaway:** Choose list comprehensions when you need a reusable collection, and generator expressions when you want to process values lazily.

### 5. Decorators

A decorator is a callable that takes another callable and returns a callable, usually adding behavior without changing the original function's core implementation.

Decorators use the `@` syntax to wrap functions.

```python
def log_call(func):
    def wrapper(*args, **kwargs):
        print(f"Calling {func.__name__}")
        return func(*args, **kwargs)

    return wrapper


@log_call
def greet(name: str):
    return f"Hello, {name}!"


print(greet("Alice"))
```

Output:

```text
Calling greet
Hello, Alice!
```

The decorator syntax is equivalent to:

```python
greet = log_call(greet)
```

When `greet()` is called, the wrapper runs first, prints a message, and delegates the actual operation to the original function.

Decorators are commonly used for:

- Logging and tracing.
- Authentication and authorization.
- Caching.
- Input validation.
- Timing function execution.
- Framework features such as route registration.

A decorator should normally preserve the wrapped function's return value and propagate exceptions unless it intentionally changes that behavior.

**Key takeaway:** Decorators let you add reusable behavior around functions without duplicating that behavior across many implementations.

### 6. Decorators with Arguments

A decorator can accept configuration arguments, allowing the same decorator to behave differently depending on how it is configured.

This requires an additional function layer: the outer function receives the configuration and returns the actual decorator.

```python
from functools import wraps


def repeat(times: int):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            result = None

            for _ in range(times):
                result = func(*args, **kwargs)

            return result

        return wrapper

    return decorator


@repeat(3)
def greet(name: str):
    print(f"Hello, {name}!")
    return name


greet("Alice")
```

Output:

```text
Hello, Alice!
Hello, Alice!
Hello, Alice!
```

The evaluation is conceptually equivalent to:

```python
greet = repeat(3)(greet)
```

The `repeat(3)` call creates a configured decorator. That decorator receives `greet` and returns the wrapper.

Notice that this example returns the result of the final invocation. Repeating a function is only appropriate when repeated execution is safe; blindly retrying operations that modify external state can cause duplicate side effects.

**Key takeaway:** Use parameterized decorators when behavior needs configuration, such as retry counts, permission requirements, or logging options.

### 7. `functools` and Function Wrapping

Python's `functools` module provides utilities for working with functions and callable objects.

One of its most important features for decorators is `functools.wraps`.

Without `@wraps`, the wrapper function can replace the original function's name, documentation, and other metadata.

```python
from functools import wraps


def log_call(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        print(f"Calling {func.__name__}")
        return func(*args, **kwargs)

    return wrapper


@log_call
def greet(name: str) -> str:
    """Return a greeting."""
    return f"Hello, {name}!"


print(greet.__name__)  # greet
print(greet.__doc__)   # Return a greeting.
```

`@wraps(func)` copies relevant metadata from the wrapped function and sets `__wrapped__`, helping tools inspect the original callable.

Other useful `functools` utilities include:

- `@functools.lru_cache`: caches results from calls with hashable arguments.
- `@functools.cache`: provides an unbounded cache.
- `functools.partial`: creates a callable with some arguments pre-filled.
- `functools.reduce`: combines iterable elements into a single result.

For example, caching expensive calculations:

```python
from functools import lru_cache


@lru_cache(maxsize=128)
def fibonacci(number: int) -> int:
    if number < 2:
        return number

    return fibonacci(number - 1) + fibonacci(number - 2)


print(fibonacci(30))
```

The cache stores previously computed results, avoiding repeated recursive calculations. Cached arguments must be hashable, and caching is appropriate only when reusing a result is safe.

**Key takeaway:** Use `functools.wraps` for custom decorators and explore the `functools` module before implementing common function utilities yourself.

### 8. Lazy Evaluation

Lazy evaluation means delaying computation until a value is actually needed. Python uses lazy evaluation in generators, generator expressions, and many iterator-based operations.

Compare eager and lazy processing:

```python
# Eager: creates a list
numbers = [number * 2 for number in range(1_000_000)]

# Lazy: creates a generator
numbers = (number * 2 for number in range(1_000_000))
```

The eager version calculates and stores all values immediately. The lazy version produces each value when requested.

Lazy evaluation can reduce memory usage and avoid unnecessary work, particularly when processing large inputs.

```python
def get_first_large_square(numbers):
    return next(
        (number ** 2 for number in numbers if number > 100),
        None,
    )


result = get_first_large_square(range(1_000_000))
print(result)  # 10201
```

The generator stops producing values as soon as `next()` finds the first matching result. It does not need to process the rest of the range.

However, laziness is not always better. It can make execution timing less obvious, and iterators may be consumed only once. Choose lazy or eager processing based on memory requirements, reuse, and readability.

**Key takeaway:** Lazy evaluation is valuable when you want to process data incrementally, stop early, or avoid building large intermediate collections.

### Key Takeaways

Iterators, generators, decorators, and lazy evaluation are closely related concepts that support Python's flexible programming model.

- **Iterables and iterators:** Understand how Python produces values during iteration.
- **Iterator protocol:** Implement custom iteration through `__iter__()` and `__next__()`.
- **Generators:** Use `yield` to create stateful iterators with less boilerplate.
- **Generator expressions:** Produce values lazily using concise syntax.
- **Decorators:** Add reusable behavior around functions.
- **Parameterized decorators:** Configure wrapping behavior through additional function layers.
- **`functools`:** Reuse utilities for metadata preservation, caching, and partial application.
- **Lazy evaluation:** Delay computation until values are requested.

These concepts are particularly useful when working with Python frameworks, database query results, streaming APIs, caching systems, and data-processing pipelines. Understanding them helps you use existing libraries effectively and design your own reusable abstractions.
