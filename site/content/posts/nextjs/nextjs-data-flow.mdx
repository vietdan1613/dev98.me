When learning the Next.js App Router, four concepts can easily get mixed up: **Fetching Data, Mutating Data, Caching, and Revalidating**. They are different operations, but they work together in a real application:

How Everything Works Together

```text
1. FETCH
   getPlants() reads plants from the database
             |
             v
2. CACHE
   Next.js caches the result
             |
             v
3. MUTATE
   An admin creates a new plant
             |
             v
4. REVALIDATE
   updateTag("plants")
   or revalidateTag("plants", "max")
   or revalidatePath("/plants")
             |
             v
5. FRESH DATA
   Next.js refreshes the relevant cached data
   according to the chosen revalidation strategy
```

### 1. Fetching Data — Reading Data

Fetching data means retrieving information from a database or API. For example, our `/plants` page needs to display all available plants. We can fetch the data directly inside a Server Component.

```tsx
export default async function PlantsPage() {
  const res = await fetch(
    "https://api.example.com/plants"
  )

  if (!res.ok) {
    throw new Error("Failed to fetch plants")
  }

  const plants = await res.json()

  return <PlantList plants={plants} />
}
```

### 2. Caching — Reusing Data

Suppose our plant catalog doesn't change frequently. We don't want to repeat the same database query unnecessarily. With **Cache Components** in Next.js 16, we can cache a function using the `"use cache"` directive.

First, enable Cache Components in `next.config.ts`:

```tsx
import type { NextConfig } from "next"

const nextConfig: NextConfig = {
  cacheComponents: true,
}

export default nextConfig
```

Then cache the function that retrieves plants:

```tsx
import { cacheLife, cacheTag } from "next/cache"

export async function getPlants() {
  "use cache"

  cacheLife("hours")
  cacheTag("plants")

  return db.plant.findMany()
}
```

### 3. Mutating Data — Changing Data

We can then connect the action to a form:

```tsx
// app/plants/new/page.tsx
import { createPlant } from "../actions"

export default function NewPlantPage() {
  return (
    <form action={createPlant}>
      <input name="name" required />
      <button type="submit">Create Plant</button>
    </form>
  )
}
```

When the form is submitted, Next.js invokes the Server Action, which inserts the new plant into the database.

### 4. Revalidating Data — Updating the Cache

Now let's look at the problem. Our database initially contains:

```text
Monstera
Philodendron
Snake Plant

-> We fetch the plants and cache the result. An admin then adds a new plant:

Ficus
```

The database now contains four plants, but the cached result may still contain only three. We need to tell Next.js that the cached data should be refreshed.

### Option 1: `revalidateTag()`

Use `revalidateTag()` when you want to invalidate or revalidate cached data associated with a specific tag.

Update our Server Action:

```tsx
"use server"

import { revalidateTag } from "next/cache"
import { db } from "@/lib/db"

export async function createPlant(formData: FormData) {
  ...

  revalidateTag("plants", "max")
}
```

Because `getPlants()` uses `cacheTag("plants")`, Next.js can identify the cached data associated with that tag.

The `"max"` profile uses stale-while-revalidate behavior: the next request may receive stale data while Next.js refreshes the cache in the background.

### Option 2: `updateTag()`

If an admin creates a plant and immediately needs to see the updated list, `updateTag()` is useful.

```tsx
"use server"

import { updateTag } from "next/cache"
import { db } from "@/lib/db"

export async function createPlant(formData: FormData) {
  ...

  updateTag("plants")
}
```

### Option 3: `revalidatePath()`

Use `revalidatePath()` when you want to revalidate a particular page or route.

For example:

```tsx
"use server"

import { revalidatePath } from "next/cache"

export async function createPlant(formData: FormData) {
  // Validate the form data and create the plant.
  // ...

  revalidatePath("/plants")
}
```

This tells Next.js to revalidate the `/plants` route. Unlike tag-based revalidation, which targets cached data associated with a tag, path-based revalidation targets a route.
