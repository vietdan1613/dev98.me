## Data Types

### 1. What are Python data types, and how does Python handle typing?

**Expectations:** Dynamic typing · Built-in types · `type()` · `None` · Operations by type

**Example answer:**

> Python data types define the kind of value a variable references and the operations supported by that value. Python is dynamically typed, meaning you don't need to declare a variable's type explicitly.
>
> Use `type()` to inspect a value's type.

```python
name = "Viet"       # str
age = 25            # int
price = 99.99       # float
is_active = True    # bool
result = None       # NoneType

print(type(age))  # <class 'int'>
```

---

### 2. What are the main collection types in Python?

**Expectations:** `list` · `tuple` · `set` · `dict` · Ordered/mutable/unique

**Example answer:**

> Python provides four common collection types:
>
> - **`list`:** Ordered, mutable, allows duplicates.
> - **`tuple`:** Ordered, immutable, allows duplicates.
> - **`set`:** Unordered, stores unique elements.
> - **`dict`:** Key-value pairs, mutable, unique keys.

```python
numbers = [1, 2, 2, 3]
coordinates = (10, 20)
unique_numbers = {1, 2, 3}
user = {"name": "Viet", "age": 25}
```

---

### 3. What is the difference between mutable and immutable types?

**Expectations:** Mutable vs immutable · `list`/`dict`/`set` · `str`/`tuple`/`int` · New object on change

**Example answer:**

> - **Mutable:** Can be modified after creation, such as `list`, `dict`, and `set`.
> - **Immutable:** Cannot be modified after creation, such as `int`, `float`, `bool`, `str`, and `tuple` (although a tuple can contain mutable objects).

```python
numbers = [1, 2]
numbers.append(3)  # Allowed

name = "Viet"
# Strings cannot be modified in place.
name = name + " Nguyen"  # Creates a new string
```

---

### 4. How do you convert between Python data types?

**Expectations:** `int`/`float`/`str`/`bool` · `ValueError` · Explicit conversion

**Example answer:**

> Use built-in functions such as `int()`, `float()`, `str()`, and `bool()`. Invalid conversions can raise exceptions such as `ValueError`.

```python
age = int("25")           # 25
price = float("19.99")    # 19.99
message = str(100)        # "100"
is_active = bool(1)       # True

int("hello")  # ValueError
```

---

### 5. What is the difference between dynamic typing and type hints?

**Expectations:** Runtime types · Annotations · Static analysis · Not enforced at runtime · FastAPI relevance

**Example answer:**

> Dynamic typing allows a variable to reference values of different types during execution. Type hints document expected types and help tools perform static analysis, but Python does not enforce them automatically at runtime.
>
> The annotations indicate the intended types of the function's arguments and return value. These fundamentals are especially useful when working with Python backend frameworks such as FastAPI.

```python
value = 10
value = "hello"  # Valid Python

def add(a: int, b: int) -> int:
    return a + b
```

## Data Structures

### 1. What are Python's built-in data structures, and when would you use each one?

**Expectations:** `list` · `tuple` · `dict` · `set` · Ordered · Mutable · Unique keys

**Example answer:**

> Python provides four main built-in collection types: `list`, `tuple`, `dict`, and `set`. I choose based on whether I need ordering, mutability, unique values, or key-based lookup.
>
> - **`list`:** Ordered, mutable, duplicates allowed.
> - **`tuple`:** Ordered, immutable, duplicates allowed.
> - **`dict`:** Insertion-ordered in modern Python, mutable, unique keys.
> - **`set`:** No guaranteed order, mutable, unique elements.
>
> For backend work, lists fit sequences, tuples fit fixed records, dictionaries fit structured lookups, and sets fit uniqueness and membership checks.

---

### 2. What is the difference between a list and a tuple?

**Expectations:** Mutable vs immutable · Append/update · Fixed groups · Unpacking

**Example answer:**

> A `list` is mutable, so elements can be added, removed, or updated. A `tuple` is immutable, so its elements cannot be reassigned after creation.
>
> Use lists for collections that change and tuples for fixed groups of values.

```python
fruits = ["apple", "banana"]
fruits.append("orange")

coordinates = (10, 20)
x, y = coordinates
```

---

### 3. How do you use dictionaries in Python?

**Expectations:** Key-value · Hashable keys · `get` · `items` · Update existing keys

**Example answer:**

> A dictionary stores key-value pairs. Keys must be hashable, and assigning an existing key updates its value. Use dictionaries when you need to retrieve values by key, such as user information or application configuration.

```python
user = {"name": "Alice", "age": 25}

user["age"] = 26
user["city"] = "Hanoi"

print(user.get("email"))  # None

for key, value in user.items():
    print(key, value)
```

---

### 4. What is a set, and when would you use it?

**Expectations:** Unique elements · Deduplication · Union/intersection · `add`/`discard`

**Example answer:**

> A set stores unique, hashable elements. It is useful for removing duplicates and performing mathematical set operations.
>
> Use `add()` to insert an element and `discard()` to remove one without raising an error if it doesn't exist.

```python
a = {1, 2, 3}
b = {3, 4, 5}

print(a | b)  # Union: {1, 2, 3, 4, 5}
print(a & b)  # Intersection: {3}
print(a - b)  # Difference: {1, 2}
```

---

### 5. What is the difference between shallow copy and deep copy?

**Expectations:** Shared nested refs · Recursive copy · `copy.copy` · `copy.deepcopy`

**Example answer:**

> A shallow copy creates a new outer collection but shares references to nested objects. A deep copy recursively copies nested objects where supported.
>
> Use a shallow copy when sharing nested objects is acceptable and a deep copy when nested data needs to be independent.

```python
import copy

original = [[1, 2], [3, 4]]
shallow = copy.copy(original)
deep = copy.deepcopy(original)

shallow[0].append(99)

print(original)  # [[1, 2, 99], [3, 4]]
print(deep)      # [[1, 2], [3, 4]]
```

---

### 6. Which common methods should you know for Python collections?

**Expectations:** List methods · Dict methods · Set methods · `remove` vs `discard`

**Example answer:**

> - **List:** `append()`, `extend()`, `insert()`, `remove()`, `pop()`, `sort()`, `reverse()`
> - **Dictionary:** `get()`, `keys()`, `values()`, `items()`, `update()`, `pop()`
> - **Set:** `add()`, `discard()`, `remove()`, `union()`, `intersection()`
>
> `remove()` on a list raises `ValueError` if the value is absent, while `discard()` on a set does not raise an error if the element is missing.

## Async Programming

### 1. How does asynchronous programming work in Python, and when should you use it?

**Expectations:** I/O-bound concurrency · `async def` · `await` · Event loop · `gather`

**Example answer:**

> Asynchronous programming allows Python to handle multiple I/O-bound tasks concurrently without blocking while waiting for operations such as network requests or database queries.
>
> Python uses `async def` to define coroutine functions, `await` to suspend a coroutine while an awaitable completes, and an event loop to coordinate asynchronous tasks.

```python
import asyncio

async def fetch_data(item_id: int) -> str:
    await asyncio.sleep(2)
    return f"Item {item_id}"

async def main():
    results = await asyncio.gather(
        fetch_data(1),
        fetch_data(2),
    )
    print(results)

asyncio.run(main())
```

---

### 2. What is the difference between synchronous and asynchronous programming?

**Expectations:** Sequential waiting · Suspend on I/O · APIs · Databases · Concurrent connections

**Example answer:**

> - **Synchronous:** Operations execute sequentially; the current flow waits for each operation to finish.
> - **Asynchronous:** A task can suspend while waiting for I/O, allowing other tasks to make progress.
>
> Async programming is especially useful for APIs, database access, and applications handling many concurrent network connections.

---

### 3. What are coroutines and the event loop?

**Expectations:** Suspend/resume · Coroutine object · Must await or schedule · Event loop coordination

**Example answer:**

> A coroutine is a computation that can suspend and resume execution. Calling an `async def` function creates a coroutine object but does not execute it to completion.
>
> The event loop coordinates asynchronous tasks and resumes them when their awaited operations make progress. The coroutine must be awaited or scheduled as a task to execute.

```python
async def fetch_data():
    await asyncio.sleep(1)
    return "Data received"
```

---

### 4. What is the difference between `asyncio.create_task()` and `asyncio.gather()`?

**Expectations:** Schedule independent task · Collect results in order · Background vs batch await

**Example answer:**

> - **`asyncio.create_task()`:** Schedules a coroutine to run as an independent task.
> - **`asyncio.gather()`:** Coordinates multiple awaitables and collects their results in input order.
>
> Use `create_task()` to schedule individual background work and `gather()` when you want to await multiple operations together.

```python
async def main():
    task = asyncio.create_task(fetch_data())
    result = await task

    results = await asyncio.gather(
        fetch_data(),
        fetch_data(),
    )
```

---

### 5. Does asynchronous programming make CPU-bound tasks faster?

**Expectations:** I/O concurrency · Event-loop blocking · Process pool · `to_thread` for blocking I/O

**Example answer:**

> No. Async programming primarily improves concurrency for I/O-bound workloads. A CPU-intensive function that runs synchronously can block the event loop.
>
> For CPU-bound work, consider a process pool or multiprocessing. For blocking I/O libraries that lack async support, `asyncio.to_thread()` can move the blocking call to a worker thread.

---

### 6. How do you run related asynchronous tasks with structured concurrency?

**Expectations:** `TaskGroup` · Shared lifetime · Cancel remaining · Exception groups · Python 3.11+

**Example answer:**

> Python 3.11 introduced `asyncio.TaskGroup`, which groups related tasks under a shared lifetime.
>
> The task group waits for its tasks to finish before exiting. If a task fails, the group cancels remaining tasks as appropriate and reports failures using an exception group.
>
> `asyncio` enables concurrent progress during I/O waits, but it does not automatically execute CPU-bound Python code in parallel.

```python
async def main():
    async with asyncio.TaskGroup() as group:
        task1 = group.create_task(fetch_data(1))
        task2 = group.create_task(fetch_data(2))

    print(task1.result(), task2.result())
```

## Concurrency

### 1. What are the differences between concurrency, parallelism, threading, multiprocessing, and asyncio in Python?

**Expectations:** Concurrency vs parallelism · Threads · Processes · Event loop · I/O vs CPU

**Example answer:**

> Python provides different ways to handle multiple tasks. The right approach depends on whether tasks spend most of their time waiting for I/O or performing CPU-intensive computations.
>
> - **Concurrency:** Multiple tasks make progress during overlapping periods.
> - **Parallelism:** Multiple tasks execute simultaneously.
> - **Threading:** Multiple threads share memory within one process.
> - **Multiprocessing:** Separate processes can execute work across CPU cores.
> - **Asyncio:** A single-threaded event loop coordinates asynchronous tasks, allowing them to make progress while others wait.

---

### 2. What is the difference between threading and multiprocessing?

**Expectations:** Shared memory · Separate processes · Blocking I/O vs CPU · Overhead · IPC

**Example answer:**

> - **Threading:** Threads share memory within one process and are best suited for blocking I/O. Communication is often through shared objects and locks, with generally lower overhead.
> - **Multiprocessing:** Separate processes have their own memory and are best suited for CPU-intensive work. Communication uses IPC, queues, or pipes, with generally higher overhead.

```python
from concurrent.futures import ThreadPoolExecutor
import time

def fetch_data(item: int) -> str:
    time.sleep(1)
    return f"Fetched {item}"

with ThreadPoolExecutor(max_workers=3) as executor:
    results = list(executor.map(fetch_data, [1, 2, 3]))
```

---

### 3. What is the Global Interpreter Lock (GIL)?

**Expectations:** One bytecode thread · I/O still overlaps · Multiprocessing for CPU · Native extensions · Free-threaded builds

**Example answer:**

> In conventional CPython builds, the GIL prevents multiple threads from executing Python bytecode simultaneously within the same interpreter.
>
> Threads can still handle I/O-bound workloads concurrently. Multiprocessing can execute CPU-intensive work in separate processes. Some native extensions release the GIL during computation, and free-threaded CPython builds have different behavior.
>
> The GIL is one reason threading usually doesn't speed up pure Python CPU-bound tasks.

---

### 4. When should you use `asyncio` instead of threading?

**Expectations:** Async libraries · Many connections · Blocking libraries → threading · Overlapping waits

**Example answer:**

> Use `asyncio` when handling many I/O operations with libraries that support asynchronous APIs, such as async HTTP clients or database drivers.
>
> Use threading when working with blocking I/O libraries that don't provide async interfaces. Asyncio can overlap waiting periods without requiring a separate thread for each task.

```python
import asyncio

async def fetch_data(item: int) -> str:
    await asyncio.sleep(1)
    return f"Fetched {item}"

async def main():
    results = await asyncio.gather(
        fetch_data(1),
        fetch_data(2),
        fetch_data(3),
    )
    print(results)

asyncio.run(main())
```

---

### 5. How do you execute CPU-bound tasks in parallel?

**Expectations:** `ProcessPoolExecutor` · Separate interpreters · Serialization overhead · `__main__` guard

**Example answer:**

> Use multiprocessing, for example with `ProcessPoolExecutor`. Each worker process has its own interpreter and memory space, allowing CPU-intensive tasks to execute in parallel.
>
> Process startup, serialization, and communication introduce overhead, so multiprocessing is most beneficial when the computation justifies those costs.

```python
from concurrent.futures import ProcessPoolExecutor

def square(number: int) -> int:
    return number * number

if __name__ == "__main__":
    with ProcessPoolExecutor() as executor:
        results = list(executor.map(square, range(5)))

    print(results)
```

---

### 6. How can you call blocking functions from asynchronous code?

**Expectations:** `asyncio.to_thread` · Worker thread · Blocking I/O · Not for pure CPU under GIL

**Example answer:**

> Use `asyncio.to_thread()` to run blocking I/O in a worker thread without blocking the event loop.
>
> This is useful for synchronous file, network, or other blocking I/O operations. It generally won't accelerate pure Python CPU-bound work under the conventional GIL.
>
> Simple rule: `asyncio` for asynchronous I/O, threading for blocking I/O, and multiprocessing for CPU-bound work.

```python
import asyncio
import time

def blocking_operation():
    time.sleep(2)
    return "Completed"

async def main():
    result = await asyncio.to_thread(blocking_operation)
    print(result)

asyncio.run(main())
```

## Error Handling & Logging

### 1. How do you make a Python application reliable when errors occur and resources need to be managed?

**Expectations:** Exceptions · Custom errors · Context managers · Logging · Cleanup

**Example answer:**

> Reliable Python applications use exception handling to control failures, custom exceptions to represent business errors, context managers to clean up resources, and logging to record useful diagnostic information.

---

### 2. How do `try`, `except`, `else`, and `finally` work?

**Expectations:** Matching exceptions · `else` on success · `finally` always · Specific catches · Re-raise

**Example answer:**

> - **`try`:** Executes code that may raise an exception.
> - **`except`:** Handles a matching exception.
> - **`else`:** Runs only if no exception occurs in `try`.
> - **`finally`:** Runs when control leaves the construct, whether an exception occurs or not.
>
> Catch specific exceptions, avoid silently ignoring errors, and re-raise exceptions when the current layer cannot handle them meaningfully.

```python
try:
    result = 10 / 2
except ZeroDivisionError:
    print("Cannot divide by zero")
else:
    print(f"Result: {result}")
finally:
    print("Operation completed")
```

---

### 3. What are custom exceptions, and why do we need them?

**Expectations:** Application-specific errors · Explicit handling · Exception hierarchy · FastAPI HTTP mapping

**Example answer:**

> Custom exceptions represent application-specific errors, allowing callers to handle different business scenarios explicitly.
>
> For larger applications, define an exception hierarchy, such as `InvalidOrderError` and `PaymentFailedError`. In FastAPI, custom exceptions can be translated into HTTP responses using exception handlers—for example, `PlantNotFoundError` can return `404 Not Found`.

```python
class PlantNotFoundError(Exception):
    pass


def get_plant(plant_id: int) -> dict:
    plant = None

    if plant is None:
        raise PlantNotFoundError(
            f"Plant {plant_id} not found"
        )

    return plant


try:
    get_plant(10)
except PlantNotFoundError as error:
    print(error)
```

---

### 4. What is a context manager, and why use `with`?

**Expectations:** Lifecycle · Automatic cleanup · `yield` setup · `finally` release · Prefer over manual close

**Example answer:**

> A context manager manages a resource's lifecycle, ensuring cleanup happens when execution leaves a block, even if an exception occurs. Prefer context managers over manual resource cleanup whenever the resource supports them.

```python
with open("data.txt", encoding="utf-8") as file:
    content = file.read()
```

```python
from contextlib import contextmanager


@contextmanager
def managed_resource():
    print("Acquire resource")
    try:
        yield "resource"
    finally:
        print("Release resource")


with managed_resource() as resource:
    print(resource)
```

---

### 5. What is the difference between `with` and `async with`?

**Expectations:** Sync vs async lifecycle · `await` for I/O · DB sessions · HTTP clients

**Example answer:**

> Both manage resource lifecycles, but `async with` is designed for asynchronous context managers. `async with` manages the session lifecycle, while `await` executes the asynchronous database operation.
>
> This pattern is useful when working with asynchronous database sessions or HTTP clients.

```python
async with session_factory() as session:
    result = await session.execute(query)
```

---

### 6. What is the difference between logging and `print()`?

**Expectations:** Levels · Handlers · Formatting · Tracebacks · `logger.exception`

**Example answer:**

> `print()` displays output, while Python's `logging` module supports severity levels, configurable handlers, structured formatting, and exception tracebacks.
>
> `logger.exception()` should be used inside an exception handler when you need the traceback.

```python
import logging

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)

try:
    result = 10 / 0
except ZeroDivisionError:
    logger.exception("Calculation failed")
```

---

### 7. What are the five common logging levels?

**Expectations:** `DEBUG` · `INFO` · `WARNING` · `ERROR` · `CRITICAL`

**Example answer:**

> - **`DEBUG`:** Detailed diagnostic information.
> - **`INFO`:** Normal application events.
> - **`WARNING`:** Unexpected but potentially recoverable conditions.
> - **`ERROR`:** An operation failed.
> - **`CRITICAL`:** A serious application-level failure.
>
> Choose the level according to the severity of the event.

---

### 8. What are common logging and exception-handling mistakes?

**Expectations:** Bare `except` · Silent ignore · Wrong layer · Duplicate logs · Secrets · Manual cleanup

**Example answer:**

> Common mistakes include using a bare `except:`, silently ignoring exceptions, handling errors at the wrong layer, logging the same exception repeatedly, logging secrets such as passwords or tokens, and manually managing resources when a context manager is available.
>
> In a real application, custom exceptions represent business failures, handlers convert them into API responses, context managers clean up sessions, and logging records failures with enough context to debug them.

## Functions

### 1. What are Python functions, and what advanced features make them flexible and reusable?

**Expectations:** `def` · Variable arguments · Closures · Higher-order functions · Type hints · Generators

**Example answer:**

> Python functions encapsulate reusable logic using `def`. Features such as variable arguments, closures, higher-order functions, type hints, and generators help developers build flexible, maintainable, and memory-efficient applications.

---

### 2. What are parameters, arguments, default values, and return values?

**Expectations:** Inputs vs values · Optional defaults · Keyword args · Implicit `None`

**Example answer:**

> Parameters define a function's inputs. Arguments are the actual values passed to the function. Default parameters allow arguments to be omitted. Return values provide results to the caller; without an explicit `return`, a function returns `None`.

```python
def create_user(name: str, role: str = "user") -> dict:
    return {"name": name, "role": role}

create_user("Alice")              # Default role: user
create_user("Bob", role="admin")  # Keyword argument
```

---

### 3. What are `*args` and `**kwargs`?

**Expectations:** Extra positional tuple · Extra keyword dict · Unpacking · Wrappers/decorators

**Example answer:**

> - **`*args`:** Collects extra positional arguments into a tuple.
> - **`**kwargs`:** Collects extra keyword arguments into a dictionary.
>
> You can also unpack collections when calling a function. These features are useful for wrappers, configurable functions, and decorators.

```python
def create_user(*args, **kwargs):
    print(args)
    print(kwargs)

create_user("Alice", 25, role="admin")
# ('Alice', 25)
# {'role': 'admin'}


def add(a: int, b: int) -> int:
    return a + b

add(*(3, 5))             # 8
add(**{"a": 3, "b": 5})  # 8
```

---

### 4. What is the LEGB rule in Python?

**Expectations:** Local · Enclosing · Global · Built-in · `global` · `nonlocal`

**Example answer:**

> LEGB describes the order Python uses to resolve variable names: Local, Enclosing, Global, then Built-in.
>
> `global` allows reassignment of a module-level variable. `nonlocal` allows reassignment of a variable in an enclosing function. Avoid unnecessary global state because it makes applications harder to test and maintain.

```python
message = "global"

def outer():
    message = "enclosing"

    def inner():
        message = "local"
        print(message)

    inner()

outer()  # local
```

---

### 5. What is a closure in Python?

**Expectations:** Inner function · Retained enclosing vars · Callbacks · Private state

**Example answer:**

> A closure is an inner function that retains access to variables from its enclosing scope, even after the outer function has returned.
>
> Common use cases include callbacks, configurable functions, and maintaining small amounts of private state.

```python
def make_multiplier(factor: int):
    def multiply(number: int) -> int:
        return number * factor

    return multiply

double = make_multiplier(2)
print(double(5))  # 10
```

---

### 6. What are lambda functions and higher-order functions?

**Expectations:** Single expression · Accept/return functions · Sorting/callbacks · Prefer `def` when complex

**Example answer:**

> A lambda is an anonymous function containing a single expression. A higher-order function accepts another function as an argument or returns a function.
>
> These concepts are useful in sorting, callbacks, decorators, and functional programming. Use `lambda` for simple expressions and prefer `def` when logic becomes complex or needs a descriptive name.

```python
square = lambda x: x ** 2
print(square(5))  # 25


def apply_operation(operation, value):
    return operation(value)

print(apply_operation(square, 4))  # 16
```

---

### 7. What are type hints, and does Python enforce them at runtime?

**Expectations:** Documentation · Static analysis · Not runtime-enforced · mypy/Pyright · FastAPI

**Example answer:**

> Type hints document the expected parameter and return types, improving readability and enabling static analysis.
>
> Python does not normally enforce type annotations at runtime. Tools such as mypy and Pyright can identify type inconsistencies before execution. Type hints are particularly useful in larger applications and FastAPI projects.

```python
def find_user(user_id: int) -> str | None:
    if user_id == 1:
        return "Alice"

    return None
```

---

### 8. What is a generator, and how does `yield` differ from `return`?

**Expectations:** Lazy values · Suspend/resume · Memory efficiency · Streaming

**Example answer:**

> A generator produces values lazily, one at a time, rather than building an entire collection in memory.
>
> - **`return`:** Returns a result and exits the function; that call does not resume.
> - **`yield`:** Produces a value and suspends execution; the generator resumes when the next value is requested.
>
> Common use cases include processing large files, streaming data, and building memory-efficient pipelines.

```python
def count_up_to(limit: int):
    for number in range(1, limit + 1):
        yield number

for number in count_up_to(3):
    print(number)
```

## PEP 8

### 1. What is PEP 8, and why is it important?

**Expectations:** Style guide · Readability · Consistency · Collaboration · Maintainability

**Example answer:**

> PEP 8 is Python's style guide for writing readable, consistent, and maintainable code. It defines conventions for naming, spacing, and line length, helping teams collaborate and review code more easily.

---

### 2. What are the main naming and formatting conventions in PEP 8?

**Expectations:** `snake_case` · `PascalCase` · `UPPER_SNAKE_CASE` · Blank lines · Line length

**Example answer:**

> - **Variables and functions:** `snake_case`, e.g. `user_name`, `calculate_total()`.
> - **Classes:** `PascalCase`, e.g. `UserService`.
> - **Constants:** `UPPER_SNAKE_CASE`, e.g. `MAX_RETRIES`.
> - **Modules:** lowercase, e.g. `user_service.py`.
> - **Blank lines:** Two around top-level definitions and one between class methods.
> - **Line length:** Traditionally 79 characters for code.

---
