## Large Language Models (LLMs)

### 1. What is an LLM, and how does it generate text?

**Expectations:** Next-token prediction · Tokenizer · Character / word / subword · BPE · Context window

**Example answer:**

> A Large Language Model (LLM) is a machine learning model trained to understand and generate text. Most modern generative LLMs predict the next token based on the tokens that came before it.
>
> For example, given `Today the weather is`, the model assigns probabilities to possible next tokens. A decoding strategy selects a token, adds it to the sequence, and repeats the process until generation finishes. LLMs contain millions or billions of learned parameters that capture patterns in their training data.
>
> LLMs process numerical representations rather than raw text. A tokenizer converts text into tokens and maps them to numerical token IDs. Common approaches include character-based, word-based, and subword-based tokenization such as Byte Pair Encoding (BPE).
>
> The context window defines how many tokens a model can process in a single context, including input and potentially generated output.

---

### 2. What are the main decoding strategies, and how do temperature, top-k, and top-p work?

**Expectations:** Greedy · Beam search · Sampling · Temperature · Top-k · Top-p · Predictability vs diversity

**Example answer:**

> Decoding determines how an LLM selects the next token. Greedy decoding selects the highest-probability token at each step. Beam search explores multiple candidate sequences and retains the most promising ones. Sampling selects tokens according to their probability distribution.
>
> Sampling can be controlled by temperature (lower values generally produce more predictable output; higher values encourage diversity), top-k (restricts sampling to the `k` most probable tokens), and top-p (restricts sampling to the smallest set of tokens whose cumulative probability reaches a specified threshold).
>
> These methods involve trade-offs between predictability, diversity, and generation quality.

| Strategy | Description |
| --- | --- |
| Greedy decoding | Selects the highest-probability token at each step. |
| Beam search | Explores multiple candidate sequences and retains the most promising ones. |
| Sampling | Selects tokens according to their probability distribution. |

---

### 3. What is the difference between foundation models and instruction-tuned models?

**Expectations:** Base / foundation · Instruction tuning · Chat roles · `system` / `user` / `assistant`

**Example answer:**

> Foundation (base) models learn language patterns from large datasets, often through next-token prediction. Instruction-tuned models receive additional training to follow instructions and respond more appropriately to user requests.
>
> For example, a base model may continue a text sequence, while an instruction-tuned model is better suited to answering questions or following task descriptions.
>
> Chat models commonly use structured messages with roles such as `system`, `user`, and `assistant`. These roles help communicate the intended structure of a conversation.

---

### 4. What are the main parameters of an LLM text generation API?

**Expectations:** `model` · `messages` · `max_tokens` · `temperature` · `top_p` · `n` · `stream`

**Example answer:**

> These parameters control model selection, conversation input, output length, and generation behavior. Exact parameter names and behavior vary by provider and model.

| Parameter | Purpose |
| --- | --- |
| `model` | Specifies which model to use. |
| `messages` | Provides conversation messages and roles. |
| `max_tokens` or an equivalent limit | Limits generated output length. |
| `temperature` | Controls sampling randomness. |
| `top_p` | Controls nucleus sampling. |
| `n` | Requests multiple output choices when supported. |
| `stream` | Returns output incrementally rather than waiting for the complete response. |

### 5. What is a local LLM, and what are its advantages and disadvantages?

**Expectations:** Local deployment · LM Studio · Privacy / cost · Hardware trade-offs · Offline use

**Example answer:**

> A local LLM runs on your own computer or infrastructure instead of relying entirely on a remotely hosted model. Tools such as LM Studio simplify downloading and running compatible models locally and can expose an API compatible with OpenAI-style integrations.
>
> Advantages include greater control over where data is processed, potentially lower recurring API costs, offline use when resources are available, and more control over model selection and deployment.
>
> Disadvantages include hardware requirements (RAM and potentially GPU), additional setup and optimization work, potentially weaker performance from smaller models, and ongoing hardware, electricity, and maintenance costs.
>
> The right choice depends on the task, hardware, privacy requirements, and performance expectations.

---

### 6. What is the difference between inference, fine-tuning, and training an LLM from scratch?

**Expectations:** Inference first · Fine-tune for adaptation · Training from scratch is costly · Pipeline understanding

**Example answer:**

> Inference runs an already-trained model to generate responses. Fine-tuning continues training a pretrained model on a more specific dataset to adapt its behavior. Training from scratch trains a model from an initial state using a large dataset and substantial computing resources.
>
> For most developers, inference is the best starting point because it enables building AI applications without training a model themselves. Fine-tuning becomes relevant when a particular use case requires adapting the model's behavior beyond what prompting or other approaches can achieve.
>
> Understand the full pipeline: text is tokenized, the model predicts the next token, and a decoding strategy selects it. Then distinguish how the model was trained, how it is deployed, and how your application controls generation through API parameters.

| Approach | Description |
| --- | --- |
| Inference | Runs an already-trained model to generate responses. |
| Fine-tuning | Continues training a pretrained model on a more specific dataset to adapt its behavior. |
| Training from scratch | Trains a model from an initial state using a large dataset and substantial computing resources. |

## Function Calling

### 1. What is function calling in LLMs, and how does it work?

**Expectations:** Tool selection · Structured arguments · App executes · Five-step loop · Model proposes

**Example answer:**

> Function calling, also known as tool calling, allows an LLM to select an appropriate function and generate structured arguments based on a user's request. The LLM typically does not execute the function itself. Instead, the application executes the requested function and returns its result to the model.
>
> The workflow consists of five steps: define tools with names, descriptions, and parameter schemas; analyze whether a tool is needed; generate a tool call with the selected function and arguments; validate and execute the function in the application; and return the tool result to the model for a natural-language answer.
>
> For example, when a user asks for the weather in Hanoi, the model might generate `{"location": "Hanoi", "unit": "celsius"}`. The application passes these arguments to a weather API and returns the result to the model.

---

### 2. How do you define tools and implement a function-calling loop?

**Expectations:** Schema · Chat Completions tools · Append tool messages · Validate · Multi-tool · Authorize

**Example answer:**

> Tools are typically described using a schema that specifies the function's name, purpose, and parameters. For example, a weather tool might require a `location` string and a `unit` restricted to `"celsius"` or `"fahrenheit"`.
>
> With OpenAI's Chat Completions API, you send `tools` with the messages, inspect `tool_calls` on the assistant message, execute matching functions, append tool-role messages with results, and call the model again for a final answer.
>
> This illustrates the basic tool-calling loop. A production implementation should also validate arguments, handle execution failures, support multiple tool calls, and ensure that each tool is authorized before execution.

```python
response = client.chat.completions.create(
    model="YOUR_SUPPORTED_MODEL",
    messages=messages,
    tools=[weather_tool],
)

assistant_message = response.choices[0].message

if assistant_message.tool_calls:
    messages.append(assistant_message)

    for tool_call in assistant_message.tool_calls:
        if tool_call.function.name == "get_current_weather":
            arguments = json.loads(
                tool_call.function.arguments
            )
            result = get_current_weather(**arguments)

            messages.append({
                "role": "tool",
                "tool_call_id": tool_call.id,
                "content": result,
            })

    final_response = client.chat.completions.create(
        model="YOUR_SUPPORTED_MODEL",
        messages=messages,
    )
```

---

### 3. What are the best practices for implementing function calling securely?

**Expectations:** Never trust model args · Strict schemas · Validate · Limit tools · AuthZ · Confirm sensitive ops

**Example answer:**

> The key principle is that model-generated tool calls must not be trusted automatically.
>
> Recommended practices include using descriptive function names and clear descriptions, defining strict parameter schemas with required fields, types, and enums, validating arguments before executing functions, handling API errors and unexpected responses, exposing only relevant tools for each request, enforcing authorization for sensitive operations, requiring confirmation for high-impact actions such as purchases or deletions, and keeping execution and permission decisions under application control.
>
> Pydantic and JSON Schema can help validate tool arguments and define consistent input contracts. Schema generation alone, however, does not create a complete provider-specific tool definition.

---

### 4. What is the difference between function calling and MCP?

**Expectations:** Interaction pattern vs protocol · Complementary · Auth still required · Full cycle ownership

**Example answer:**

> Function calling is a model interaction pattern: the LLM selects a tool and generates structured arguments. Model Context Protocol (MCP) is a protocol that standardizes how AI applications connect to external tools and data sources.
>
> An MCP server can expose tools to compatible clients, while an LLM's function-calling capabilities can help decide when to invoke them. The two concepts are complementary rather than interchangeable. MCP does not remove the need for authorization, argument validation, or safe tool execution.
>
> Remember the complete cycle: define tool → model requests tool → application validates and executes → result returns to model → final answer. The LLM proposes the action; your application remains responsible for executing it safely.

## Embeddings

### 1. What are embeddings, and why are they important in AI applications?

**Expectations:** Numerical vectors · Map of meaning · Semantic search · Clustering · Recommendations · Learned dimensions

**Example answer:**

> Embeddings are numerical vectors that represent data such as text, images, and other content. They allow machine learning systems to compare relationships between items based on their learned representations.
>
> Think of embeddings as a map of meaning. Words or sentences with similar meanings may appear close together in embedding space, just as nearby cities appear close together on a geographical map. For example, `"I love dogs"` and `"I like puppies"` may have similar embeddings even though their wording differs.
>
> Embeddings are useful for semantic search, clustering, recommendations, classification, and anomaly detection. Unlike manually assigned labels, embedding dimensions are learned representations and are not necessarily directly interpretable.

---

### 2. How do you measure similarity between embeddings, and what is the role of a Vector Database?

**Expectations:** Cosine / Euclidean / Dot product · Vector DB stores and retrieves · ANN · Model vs metric vs DB

**Example answer:**

> Once data is converted into vectors, similarity or distance metrics can compare those vectors. Cosine similarity measures the angle between vectors, Euclidean distance measures the straight-line distance, and the dot product combines corresponding vector components into a single score.
>
> A Vector Database stores embeddings alongside their original content and metadata, then retrieves similar vectors efficiently. For larger datasets, it can use Approximate Nearest Neighbor (ANN) algorithms to reduce search time, often trading some retrieval accuracy for speed.
>
> The distinction is that the embedding model generates vectors, the similarity metric compares them, and the Vector Database stores and retrieves them.

```python
from sentence_transformers import SentenceTransformer
from sentence_transformers.util import cos_sim

model = SentenceTransformer("all-MiniLM-L12-v2")

sentences = [
    "I love dogs.",
    "I like puppies.",
    "The stock market is rising.",
]

embeddings = model.encode(sentences)

similarity = cos_sim(
    embeddings[0],
    embeddings[1],
)

print(similarity.item())
```

---

### 3. How do embeddings work in a RAG application?

**Expectations:** Chunk → embed → store → query embed → retrieve → LLM · Same model · Quality factors

**Example answer:**

> Retrieval-Augmented Generation (RAG) combines document retrieval with LLM-generated answers. A typical workflow chunks documents, generates embeddings for each chunk, stores vectors with text and metadata in a Vector Database, embeds the user query with the same embedding model, retrieves the most similar chunks (optionally with metadata filters), and provides the retrieved content and question to an LLM.
>
> Importantly, the embedding model retrieves potentially relevant information; it does not generate the final answer. RAG quality also depends on chunking, retrieval strategy, embedding quality, and source data.
>
> Remember the three essential concepts: embeddings represent data numerically, similarity metrics compare vectors, and Vector Databases retrieve relevant information. In RAG, these components help an LLM access external knowledge before generating an answer.

```python
query = "How do I reset my password?"
query_embedding = model.encode(query)
matches = vector_db.search(query_embedding, top_k=3)

context = "\n\n".join(
    match["text"] for match in matches
)

prompt = f"""Use the context below to answer the question.
If the answer is not in the context, say you do not know.

Context:
{context}

Question:
{query}
"""
```

## Vector Databases

### 1. What is a Vector Database, and why do AI applications use it?

**Expectations:** Store / index / retrieve embeddings · Metadata · ANN · Persistence · Filtering · Scale

**Example answer:**

> A Vector Database is a database designed to store, index, and retrieve vector embeddings efficiently. Each vector can be associated with original content and metadata, such as a document, product description, or image.
>
> For example, an online store can convert product descriptions into embeddings to retrieve semantically similar products, even when their wording differs.
>
> Vector Databases are useful because they provide persistent vector storage, similarity search, metadata filtering, indexing for efficient retrieval, and scalable access to larger datasets.
>
> Without indexing, an application may need to compare a query against every stored vector. Vector Databases can use Approximate Nearest Neighbor (ANN) algorithms to retrieve likely matches more efficiently, usually trading some accuracy for speed.

---

### 2. How does vector similarity search work?

**Expectations:** Embed → store → query embed → nearest neighbors · Cosine / Euclidean / Dot · Compatible model

**Example answer:**

> A typical vector search workflow converts documents or products into embeddings, stores the vectors alongside content and metadata, converts the user's query into an embedding using a compatible model, finds the nearest vectors using a selected similarity or distance metric, and returns the corresponding documents or products.
>
> Cosine similarity measures the angle between two vectors. Other options include Euclidean distance and the dot product. For example, searching for `"pink windbreaker jacket"` may retrieve a product described as `"áo khoác gió màu hồng"` if their embeddings are sufficiently similar.
>
> With ChromaDB, `collection.query()` works when the collection has a compatible embedding function configured. Otherwise, query embeddings can be supplied directly.

```python
import numpy as np

def cosine_similarity(a, b):
    return np.dot(a, b) / (
        np.linalg.norm(a) * np.linalg.norm(b)
    )
```

```python
results = collection.query(
    query_texts=["pink windbreaker jacket"],
    n_results=2,
)

print(results)
```

---

### 3. What are the common use cases for Vector Databases?

**Expectations:** Semantic search · Recommendations · Image retrieval · RAG · Anomaly detection

**Example answer:**

> Vector Databases support applications that need to find related information based on similarity: semantic search, recommendation systems, image retrieval, RAG applications, and anomaly detection.
>
> In a RAG system, documents are embedded and indexed. When a user asks a question, the system retrieves relevant passages and supplies them to an LLM to help generate a grounded response.

---

### 4. What is the difference between dedicated Vector Databases and traditional databases with vector search?

**Expectations:** Dedicated vs extension · Chroma / Qdrant / Weaviate / Milvus / Pinecone · pgvector · Trade-offs

**Example answer:**

> Dedicated Vector Databases focus on vector retrieval, while traditional databases can provide vector search alongside their existing capabilities.
>
> If your application already uses PostgreSQL, `pgvector` can be attractive because you can store embeddings alongside relational data without introducing another database service. The best choice depends on data size, filtering requirements, latency, scalability, deployment complexity, and cost.

| Database | Typical use case |
| --- | --- |
| ChromaDB | Learning, prototyping, and local applications |
| Qdrant | Vector search with metadata filtering |
| Weaviate | Vector and hybrid search |
| Milvus | Large-scale vector retrieval |
| Pinecone | Managed vector database service |
| PostgreSQL + pgvector | Vector search alongside relational data |
| SQLite + sqlite-vec | Lightweight local applications |
| Redis | Vector search alongside Redis capabilities |
| Elasticsearch | Keyword, vector, and hybrid search |

---

### 5. Do you always need a Vector Database?

**Expectations:** Small data in-memory OK · Need DB for persistence / ANN / filtering / scale · Embeddings vs Vector DB vs RAG

**Example answer:**

> No. For small datasets, storing embeddings in memory and calculating similarities directly may be sufficient. For example, a product catalog containing a few hundred or thousand vectors might not need a dedicated vector-search service.
>
> A Vector Database becomes more useful when you need persistent storage, efficient indexing, metadata filtering, concurrent access, or larger-scale retrieval.
>
> Understand the distinction between embeddings and Vector Databases: embeddings represent data as vectors, while Vector Databases store and retrieve those vectors efficiently. For RAG, the database retrieves relevant context; the LLM uses that context to generate an answer.

## Weaviate

### 1. What is the difference between `near_text`, `hybrid`, and `near_object` in Weaviate?

**Expectations:** Semantic `near_text` · BM25 + vector `hybrid` · Similarity via `near_object` · Use-case mapping

**Example answer:**

> Weaviate provides three common query methods for retrieving relevant objects. `near_text` searches by semantic meaning using vectors and is best for natural-language search. `hybrid` combines keyword-based BM25 search with vector search when exact terms and semantic relevance both matter. `near_object` uses an existing object's vector to find similar objects, which is useful for product or movie recommendations.
>
> Use `near_text` when users describe what they want in natural language, `hybrid` when keyword matches also matter, and `near_object` when you already have an object and want to find similar ones.

| Method | How it works | Best use case |
| --- | --- | --- |
| `near_text` | Searches by semantic meaning using vectors | Natural-language search |
| `hybrid` | Combines keyword-based BM25 search with vector search | Search requiring both exact terms and semantic relevance |
| `near_object` | Uses an existing object's vector to find similar objects | Product or movie recommendations |

```python
# Semantic search
response = movie_collection.query.near_text(
    query="funny children story",
    limit=5,
)

# Hybrid search
response = movie_collection.query.hybrid(
    query="thriller",
    alpha=0.5,
    limit=5,
)

# Find objects similar to an existing object
response = movie_collection.query.near_object(
    near_object=object_id,
    limit=5,
)
```

---

### 2. How does hybrid search work in Weaviate, and what does `alpha` control?

**Expectations:** BM25 + vector · `alpha` 0 / 0.5 / 1 · Keyword vs semantic balance

**Example answer:**

> Hybrid search combines BM25 keyword matching with vector search based on embedding similarity. The `alpha` parameter controls the balance: `0` is keyword search, `0.5` is a balanced combination, and `1` is vector search.
>
> For example, searching for `"thriller"` can retrieve movies that explicitly contain the genre keyword while also finding semantically related movies. Hybrid search is useful when neither keyword matching nor semantic search alone provides the desired results.

| Alpha | Behavior |
| --- | --- |
| `0` | Keyword search |
| `0.5` | Balanced combination |
| `1` | Vector search |

---

### 3. How does `near_object` work, and what is a UUID used for?

**Expectations:** Existing object vector · UUID identity · Stable IDs · Similarity depends on embeddings · Filters

**Example answer:**

> `near_object` uses the vector associated with an existing object to retrieve nearby vectors in the same collection. For example, a movie recommendation system can find films similar to Hard Kill without requiring the user to enter a text query.
>
> Each Weaviate object has a UUID that identifies it. You can let Weaviate generate the UUID or provide one yourself when inserting an object. A stable UUID makes it easier to reference an object across application workflows. The referenced object must exist for a similarity query to work, and similarity depends on how its vector was generated.
>
> Remember the distinction: `near_text` searches from a text query, `hybrid` combines keyword and vector retrieval, and `near_object` searches from an existing object's vector. These methods can also be combined with metadata filters to make retrieval more precise.

```python
response = movie_collection.query.near_object(
    near_object=object_id,
    limit=5,
)
```

## Retrieval-Augmented Generation (RAG)

### 1. What is RAG, and why do LLM applications need it?

**Expectations:** Retrieve + generate · External knowledge · Updated / private data · Citations · Hallucinations remain

**Example answer:**

> Retrieval-Augmented Generation (RAG) is a technique that combines information retrieval with text generation. It allows an LLM to answer questions using relevant information retrieved from external sources, such as documents, databases, or APIs, rather than relying only on knowledge learned during training.
>
> For example, a plant-shop chatbot can retrieve the latest plant-care guides or product information before generating an answer.
>
> RAG helps applications access updated information without retraining the LLM for every change, answer questions using private or domain-specific documents, provide source citations so users can verify answers, and reduce the need to include an entire knowledge base in every prompt.
>
> However, RAG does not eliminate hallucinations. The system can retrieve irrelevant documents or the LLM can misinterpret the supplied context.

---

### 2. How does a RAG pipeline work?

**Expectations:** Indexing vs query time · Chunk · Embed · Retrieve · Compatible embedding model · Access control

**Example answer:**

> A basic RAG pipeline consists of two phases: indexing, and retrieval and generation.
>
> **Phase 1: Indexing** — Collect documents, chunk them, generate embeddings, and store vectors, content, and metadata.
>
> **Phase 2: Retrieval and generation** — Embed the user question, retrieve relevant documents, then send the LLM the retrieved context with the question to produce an answer.
>
> The indexing phase prepares the knowledge base and runs again when the source data changes. Important considerations include using a compatible embedding model for both document indexing and query embedding, choosing chunk sizes that preserve enough context, applying access control during retrieval, and including source metadata when citations are needed.
>
> A vector database is common but not mandatory. Retrieval can also use keyword search, SQL queries, external APIs, or a combination of methods.

```text
User question → Query embedding
Retrieve relevant documents
LLM + retrieved context → Answer
```

---

### 3. What is the difference between Naive RAG, Advanced RAG, and Modular RAG?

**Expectations:** Naive retrieve-and-generate · Advanced improvements · Modular components · Not strict standards

**Example answer:**

> Naive RAG retrieves relevant chunks and sends them directly to the LLM. Advanced RAG improves retrieval with query rewriting, metadata filtering, hybrid search, reranking, and better context construction. Modular RAG separates retrieval, preprocessing, ranking, generation, and other stages into configurable components.
>
> Naive RAG is a good starting point, but it can return irrelevant or duplicate chunks. Advanced RAG improves retrieval quality, while Modular RAG makes it easier to customize the pipeline for different use cases. These are broad architectural descriptions rather than universally standardized categories.

| Architecture | Description |
| --- | --- |
| Naive RAG | Retrieves relevant chunks and sends them directly to the LLM. |
| Advanced RAG | Improves retrieval with query rewriting, metadata filtering, hybrid search, reranking, and better context construction. |
| Modular RAG | Separates retrieval, preprocessing, ranking, generation, and other stages into configurable components. |

---

### 4. What is the difference between RAG and function calling?

**Expectations:** Knowledge vs tools · Different model outputs · Can combine both

**Example answer:**

> RAG retrieves knowledge; function calling allows an LLM to select and request the execution of a tool. RAG typically produces an answer grounded in retrieved context, while function calling produces a structured tool call with arguments that the application executes.
>
> For example, a shopping assistant could use function calling to check an order's status and RAG to retrieve the store's return policy. Both approaches can be combined in a single application.

| Aspect | RAG | Function calling |
| --- | --- | --- |
| Purpose | Retrieve relevant information | Select and invoke tools |
| Typical use | Search documents and answer questions | Call APIs or execute operations |
| Model output | Answer grounded in retrieved context | Structured tool call with arguments |
| Execution | Application retrieves information | Application executes the requested function |

---

### 5. Why use RAG instead of a long context window?

**Expectations:** Scale · Relevance · Cost / latency · Citations · Permissions · Combine when useful

**Example answer:**

> A long context window allows an LLM to process a large amount of text in one request. RAG retrieves only the information relevant to a particular question.
>
> RAG is particularly useful when the knowledge base is too large to include in every request, only a small subset of documents is relevant to each question, token costs and latency need to be controlled, or the application needs document-level citations or access permissions.
>
> Long-context prompting can be preferable when the relevant material is manageable and the task benefits from seeing the entire document. Some applications combine both approaches.

---

### 6. How do you improve RAG retrieval quality in production?

**Expectations:** Hybrid search · Reranking · Chunking · Evaluation · Access control · Citations · Agentic RAG · MCP distinction

**Example answer:**

> Several techniques can improve retrieval quality, reliability, and security: hybrid search combines semantic similarity with keyword matching; reranking reorders retrieved candidates; chunking optimization preserves meaningful context; evaluation measures retrieval relevance, answer correctness, and groundedness; access control ensures retrieved documents are authorized; citations include source metadata; and agentic RAG allows an agent to decide when additional retrieval or tool use is necessary.
>
> The Model Context Protocol (MCP) can connect AI applications to external tools and data sources, but it is a tool-integration protocol rather than a RAG technique itself.
>
> Remember the core pipeline: index documents → retrieve relevant context → generate an answer. A strong RAG implementation depends not just on the LLM, but also on retrieval quality, chunking, access control, and evaluation.

## AI Gateway

### 1. What is an AI Gateway, and why would you introduce one into a FastAPI application?

**Expectations:** Central layer · Decouple providers · Routing · Streaming · Cache · Concurrency · Guardrails · Incremental adoption

**Example answer:**

> An AI Gateway is a central layer between an application and LLM providers such as OpenAI, DeepSeek, and Gemini. It separates application logic from provider-specific implementations.
>
> Without a gateway, provider integration, caching, routing, streaming, and security logic can become tightly coupled to API routes. The gateway can provide provider abstraction, model routing based on cost, latency, or request complexity, consistent streaming responses, semantic caching, concurrent context retrieval, and centralized security and guardrails.
>
> You don't need every feature immediately. Start with provider abstraction and introduce additional components as the application grows.

```text
Client → FastAPI → AI Gateway → LLM Providers
                                  ├── OpenAI
                                  ├── DeepSeek
                                  └── Gemini
```

---

### 2. How would you design provider abstraction and model routing in an AI Gateway?

**Expectations:** Protocol interface · Provider implementations · Route by cost / complexity · Abstraction vs routing

**Example answer:**

> Define a common interface that each provider implements. This allows application logic to depend on an abstraction rather than a specific vendor. Each provider implements the same interface, allowing the gateway to select a provider without changing the rest of the application.
>
> Model routing determines which model handles a request. For example, simple requests go to a cheaper model, general requests to a standard model, and complex requests to a more capable model. Routing decisions can consider request complexity, model capabilities, cost, latency, and user permissions.
>
> Provider abstraction and model routing solve different problems: abstraction standardizes how providers are called, while routing decides which provider or model should be called.

```python
from typing import AsyncIterator, Protocol


class LLMProvider(Protocol):
    async def generate(self, messages, model: str):
        ...

    def stream(
        self,
        messages,
        model: str,
    ) -> AsyncIterator[str]:
        ...
```

---

### 3. How would you implement streaming and concurrent operations in an AI Gateway?

**Expectations:** SSE · `StreamingResponse` · Normalize providers · `asyncio.TaskGroup` · Independent tasks

**Example answer:**

> Streaming allows the application to deliver generated content incrementally rather than waiting for the entire response. FastAPI can use `StreamingResponse` with `text/event-stream` to expose a Server-Sent Events (SSE) endpoint. The gateway normalizes provider-specific streaming formats so the frontend can consume a consistent event format.
>
> Concurrent operations reduce latency when independent tasks need to run before generation, such as retrieving documents, user data, and conversation history. Because these tasks run concurrently with `asyncio.TaskGroup`, total waiting time can approach that of the slowest task instead of the sum of all three, assuming the operations are genuinely independent.

```text
LLM Provider → AI Gateway → SSE → React UI
```

```python
import asyncio


async def gather_context():
    async with asyncio.TaskGroup() as group:
        rag_task = group.create_task(search_rag())
        user_task = group.create_task(get_user())
        history_task = group.create_task(get_history())

    return (
        rag_task.result(),
        user_task.result(),
        history_task.result(),
    )
```

### 4. What is semantic caching, and what challenges does it introduce?

**Expectations:** Similar-meaning reuse · Embeddings · Thresholds · Expiration · Permissions · Stale data

**Example answer:**

> Semantic caching reuses a previous response when a new query is sufficiently similar in meaning to a cached query. For example, `"What is the price of Monstera?"` and `"How much does Monstera cost?"` may share intent.
>
> A semantic cache can embed the incoming query and search for a sufficiently similar cached query. If a suitable match exists, it returns the cached response; otherwise, the gateway calls the LLM. This can reduce API costs and latency.
>
> However, similarity alone doesn't guarantee that a cached answer is correct. Production implementations should consider similarity thresholds, cache expiration and invalidation, user permissions and data isolation, model and prompt configuration, and changes to underlying information such as product prices.

---

### 5. How would you secure an AI Gateway?

**Expectations:** Request validation · API keys · Prompt injection · PII · Access control · Layered defenses

**Example answer:**

## Text Chunking in RAG

### 1. What is text chunking, and why is it important in RAG?

**Expectations:** Split before embed · Retrieval quality · Size trade-offs · Chunk → embed → store → retrieve → LLM

**Example answer:**

> Text chunking is the process of splitting documents into smaller pieces before generating embeddings and storing them in a vector database. It helps a RAG system retrieve relevant information more efficiently instead of searching through entire documents.
>
> A typical workflow is: split documents into chunks, generate embeddings for each chunk, store embeddings and associated content in a vector database, retrieve relevant chunks when a user asks a question, and pass the retrieved context to an LLM to generate an answer.
>
> Chunking affects retrieval quality because chunks that are too large may contain irrelevant information, while chunks that are too small may lose important context.

---

### 2. How does LangChain's `RecursiveCharacterTextSplitter` work?

**Expectations:** Prioritized separators · `chunk_size` / `chunk_overlap` · Default separators · Overlap across boundaries

**Example answer:**

> `RecursiveCharacterTextSplitter` splits text using a prioritized list of separators. It attempts to preserve natural boundaries, such as paragraphs and newlines, before falling back to smaller boundaries.
>
> Main parameters include `chunk_size` (default 4,000 characters), `chunk_overlap` (default 200), `length_function` (defaults to `len()`), and `separators` (defaults to `["\n\n", "\n", " ", ""]`).
>
> Overlap preserves some content across adjacent chunks, reducing the risk that relevant information will be lost when a sentence or concept crosses a chunk boundary. Actual sizes and overlap can vary depending on the text and available separators.

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter

text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=100,
    chunk_overlap=40,
)

chunks = text_splitter.split_text(document)
```

### 3. What is the difference between paragraph-based chunking and recursive character-based chunking?

**Expectations:** Paragraph simplicity · Variable lengths · Recursive consistency · When each fits

**Example answer:**

> Paragraph-based chunking splits at paragraph boundaries and is simple to implement, but chunk lengths can vary significantly and may create oversized paragraphs. Recursive character-based chunking tries multiple separators in priority order, offers configurable chunk sizes and overlap, produces more consistently sized chunks, and can split long paragraphs further.
>
> Paragraph-based chunking is useful when paragraphs are meaningful units. Recursive character-based chunking is a practical starting point when you need more control over chunk sizes while attempting to preserve natural text boundaries.

| Paragraph-based | Recursive character-based |
| --- | --- |
| Splits at paragraph boundaries | Tries multiple separators in priority order |
| Simple to implement | Offers configurable chunk sizes and overlap |
| Chunk lengths can vary significantly | Produces more consistently sized chunks |

### 4. How do you choose a chunking strategy for different document types?

**Expectations:** Structure-aware splitting · Document-type table · LangChain splitters · Start recursive, specialize later

**Example answer:**

> The strategy should reflect the structure of the source data. For PDF, split by paragraphs, pages, or semantic sections. For source code, split by files, classes, functions, or modules. For JSON, preserve meaningful objects. For Markdown, split by headings and sections. For HTML, extract relevant content and split using structural information.
>
> For example, splitting source code every 100 characters may separate a function definition from its implementation. Splitting by function or class helps preserve meaningful code units.
>
> LangChain provides splitters such as `CharacterTextSplitter`, `RecursiveCharacterTextSplitter`, `MarkdownHeaderTextSplitter`, `HTMLHeaderTextSplitter`, `HTMLSectionSplitter`, and `MarkdownTextSplitter`.
>
> Start with `RecursiveCharacterTextSplitter` for general text, then consider document-specific chunking when structure matters. The goal is to preserve meaningful context while creating chunks that can be retrieved efficiently in a RAG pipeline.

| Document type | Recommended strategy |
| --- | --- |
| PDF | Split by paragraphs, pages, or semantic sections |
| Source code | Split by files, classes, functions, or modules |

## LangChain

### 1. What is LangChain, and what problems does it solve?

**Expectations:** Orchestration framework · Standardized interfaces · Reusable components · Abstractions vs direct SDKs

**Example answer:**

> LangChain is an open-source framework for building applications powered by Large Language Models (LLMs). It provides reusable components and standardized interfaces for connecting models with documents, vector databases, external APIs, and other data sources.
>
> Its main benefits include standardized interfaces across model providers, reusable components such as document loaders, text splitters, embeddings, and vector stores, and faster development by reducing integration code.
>
> However, LangChain introduces abstractions and additional dependencies. For simple applications with only a few model API calls, using a provider's SDK directly may be easier to maintain.

---

### 2. How would you build a PDF question-answering application using LangChain and RAG?

**Expectations:** Load → chunk → embed → store → retrieve → generate · Production concerns

**Example answer:**

> A PDF question-answering application typically follows this workflow: load documents with a loader such as `PyMuPDFLoader`, chunk with `RecursiveCharacterTextSplitter`, embed and store chunks in ChromaDB, retrieve chunks relevant to the user's question, and pass the retrieved context and question to an LLM to generate an answer.
>
> After loading, splitting, embedding, and storing document chunks, you add a retriever, an LLM, and a prompt to complete the question-answering pipeline.
>
> For production, consider source citations, document-level access controls, retrieval evaluation, error handling, and mechanisms to update or delete indexed documents.

```python
from langchain_community.document_loaders import PyMuPDFLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter
```

### 4. What are LangChain's limitations, and what alternatives would you consider?
