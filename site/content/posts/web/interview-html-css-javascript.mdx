# HTML

## 1. What are semantic HTML elements, and why are they important?

**Keywords:** `semantic` · `meaning` · `header` · `nav` · `main` · `article` · `section` · `footer`

Semantic HTML elements describe their meaning clearly for humans and machines. Examples include `<header>`, `<nav>`, `<main>`, `<article>`, `<section>`, and `<footer>`.

---

## 2. How do semantic elements improve accessibility?

**Keywords:** `screen readers` · `structure` · `purpose` · `a11y`

Screen readers can better understand the structure and purpose of the page when landmarks and semantic tags are used correctly.

---

## 3. Inline vs inline-block vs block?

**Keywords:** `inline` · `no new line` · `block` · `new line` · `inline-block` · `width/height`

Inline elements stay in the text flow and do not start on a new line. Block elements start on a new line and take full available width. Inline-block stays in flow like inline but allows setting width and height.

---

## 4. How do you improve accessibility on a website?

**Keywords:** `semantic HTML` · `alt text` · `labels` · `keyboard navigation` · `focus` · `color contrast` · `ARIA` · `testing`

Start with semantic HTML and landmarks, give images meaningful `alt` text, and connect form inputs to `<label>` elements. Make everything usable with the keyboard, with a visible focus state, and keep enough color contrast. Use ARIA only when native HTML can't express the behavior. Test with a screen reader and tools like Lighthouse or axe.

---

# CSS

## 1. How do you use CSS in a React project?

**Keywords:** `Tailwind CSS` · `utility-first` · `styling`

Use Tailwind CSS for utility-first styling so most UI can be built with small, composable classes in the markup.

---

## 2. Difference between Flexbox and Grid?

**Keywords:** `Flexbox` · `one-dimensional` · `Grid` · `two-dimensional`

Flexbox lays out items in one direction (row or column). Grid lays out items in two dimensions (rows and columns).

---

## 3. What are the CSS `position` values?

**Keywords:** `static` · `relative` · `absolute` · `fixed` · `sticky`

Common values are `static`, `relative`, `absolute`, `fixed`, and `sticky`. Each controls how an element is placed relative to the normal flow, a positioned ancestor, or the viewport.

---

## 4. `display: none` vs `visibility: hidden`?

**Keywords:** `display: none` · `remove from layout` · `visibility: hidden` · `hide but keep space`

`display: none` removes the element from the layout. `visibility: hidden` hides it visually but still reserves its space.

---

## 5. What are CSS pre-processors?

**Keywords:** `Sass` · `Less` · `variables` · `nesting` · `mixins` · `functions`

Pre-processors like Sass and Less extend CSS with variables, nesting, mixins, and functions to make styles more modular and reusable.

---

## 6. When would you use a pre-processor?

**Keywords:** `large projects` · `modular` · `maintainable` · `reusable`

Use a pre-processor on larger projects that need modular, maintainable, and reusable stylesheets.

---

## 7. What is Tailwind CSS?

**Keywords:** `utility-first` · `CSS framework` · `small classes`

Tailwind CSS is a utility-first CSS framework that builds UI from small, single-purpose classes.

---

## 8. When would you choose Tailwind over SCSS or CSS Modules?

**Keywords:** `rapid development` · `consistent design` · `less CSS bloat`

Choose Tailwind when you want faster UI work, consistent design tokens, and less custom CSS to maintain.

---

## 9. What does utility-first mean?

**Keywords:** `single-purpose classes` · `compose in markup`

A utility-first approach builds components by composing small utility classes directly in the markup instead of writing large custom CSS rules first.

---

## 10. How does Tailwind handle responsive design?

**Keywords:** `mobile-first` · `breakpoints` · `responsive prefixes`

Tailwind uses mobile-first breakpoints so styles scale up with prefixes like `sm:`, `md:`, and `lg:`.

---

## 11. How does dark mode work in Tailwind?

**Keywords:** `dark class` · `root element` · `variant`

Dark mode is typically enabled by adding a `dark` class on a root element and using `dark:` variants for alternate styles.

---

## 12. What is `@apply`, and when should you use it?

**Keywords:** `@apply` · `compose utilities` · `custom class` · `use sparingly`

`@apply` lets you compose utility classes into a custom CSS class. Prefer utilities in markup first; use `@apply` sparingly when a repeated pattern needs a named class.

---

# JavaScript

## 1. What is a closure in JavaScript?

**Keywords:** `Function` · `Lexical Scope` · `Remember Variables`

A closure is when a function remembers and can access variables from its enclosing scope, even after that outer function has finished running.

---

## 2. What is hoisting?

**Keywords:** `Declarations` · `Top of Scope` · `TDZ`

Hoisting moves variable and function declarations to the top of their scope during compilation. `var` is hoisted and initialized as `undefined`. `let` and `const` are hoisted but sit in the temporal dead zone until their declaration line runs.

---

## 3. How does scope work in JavaScript?

**Keywords:** `Global` · `Function` · `Block`

JavaScript has global scope, function scope, and block scope (for `let` and `const`).

---

## 4. What is the difference between `var`, `let`, and `const`?

**Keywords:** `Function-scoped` · `Block-scoped` · `Reassignment`

`var` is function-scoped and can be redeclared. `let` is block-scoped and cannot be redeclared in the same scope. `const` is block-scoped and cannot be reassigned after initialization.

---

## 5. How does `this` work in JavaScript?

**Keywords:** `Call Site` · `Context` · `Binding`

The value of `this` depends on how the function is called—not where it is defined.

---

## 6. What is the difference between `call`, `apply`, and `bind`?

**Keywords:** `Invoke` · `Arguments` · `Fixed this`

`call` invokes a function with a given `this` and arguments listed individually. `apply` invokes with arguments as an array. `bind` returns a new function with `this` permanently bound.

---

## 7. What happens when you use `new` with a function?

**Keywords:** `Object` · `Prototype` · `Constructor`

Using `new` creates a new object, sets its prototype, binds `this` to that object, runs the function body, and returns the object (unless the constructor explicitly returns something else).

---

## 8. What is the JavaScript event loop?

**Keywords:** `Call Stack` · `Tasks` · `Non-blocking`

The event loop coordinates running synchronous code on the call stack, then draining microtasks, then macrotasks, so JavaScript can stay responsive while handling async work.

---

## 9. What are microtasks vs macrotasks?

**Keywords:** `Promises` · `setTimeout` · `Order`

Microtasks (for example Promise callbacks) run before the next macrotask (for example `setTimeout` callbacks). That ordering affects when async code runs relative to timers and I/O.

---

## 10. What are common async patterns?

**Keywords:** `Callbacks` · `Promises` · `async/await`

Common patterns are callbacks, Promises (chaining and `Promise.all`), and `async/await` for writing asynchronous code in a more synchronous style.

---

## 11. What is the difference between `setTimeout` and `setInterval`?

**Keywords:** `Once` · `Repeat` · `Delay`

`setTimeout` runs a callback once after a delay. `setInterval` runs a callback repeatedly on a fixed interval until cleared.

---

## 12. What is prototype inheritance?

**Keywords:** `Prototype Chain` · `Objects` · `Lookup`

Objects inherit properties and methods from their prototype via the prototype chain. When a property is missing on the object, JavaScript looks up the chain.

---

## 13. What is the difference between `==` and `===`?

**Keywords:** `Coercion` · `Strict` · `Type`

`==` compares with type coercion when types differ. `===` is strict equality: no coercion, so type and value must match.

---

## 14. What is the difference between `null` and `undefined`?

**Keywords:** `No Value` · `Unassigned` · `Intentional`

`null` is an assigned value meaning “no value” (often intentional). `undefined` means a variable was declared but not assigned, or a missing property.

---

## 15. What are JavaScript data types?

**Keywords:** `Primitive` · `Object` · `typeof`

Primitives include string, number, boolean, null, undefined, symbol, and bigint. Non-primitives include object (and arrays and functions, which are objects).

---

## 16. Shallow copy vs deep copy?

**Keywords:** `Reference` · `Nested Objects` · `Clone`

A shallow copy duplicates the top level but keeps references to nested objects. A deep copy recursively clones nested structures so copies are independent.

---

## 17. What is immutability?

**Keywords:** `No Mutation` · `New Data` · `Predictable State`

Immutability means not changing existing data in place; you create new data instead. That makes state updates easier to reason about and debug.

---

## 18. What is event delegation?

**Keywords:** `Bubbling` · `Parent Listener` · `Dynamic Children`

Event delegation attaches one listener on a parent and handles events from children using event bubbling. It works well for lists and dynamically added elements.

---

## 19. How do you stop event propagation?

**Keywords:** `stopPropagation` · `Bubbling` · `Capture`

Call `event.stopPropagation()` on the event object to prevent the event from bubbling (or capturing) to ancestor elements.

---

## 20. What is a memory leak in JavaScript?

**Keywords:** `Unreachable` · `Retained` · `Heap`

A memory leak happens when memory that is no longer needed stays allocated because something still holds a reference to it.

---

## 21. What are common causes of memory leaks?

**Keywords:** `Listeners` · `Timers` · `Closures`

Common causes include event listeners that are never removed, timers that are never cleared, and closures that keep large objects alive longer than necessary.

---

## 22. How can you prevent memory leaks?

**Keywords:** `Cleanup` · `removeEventListener` · `clearTimeout`

Remove event listeners when components or nodes are destroyed, clear timers and intervals, and avoid keeping unnecessary references in globals or long-lived closures.

---

## 23. What is garbage collection?

**Keywords:** `Reachability` · `Automatic` · `GC`

Garbage collection is automatic memory management: the runtime frees objects that are no longer reachable from the root set (globals, active stack, etc.).

---

## 24. How do you improve JavaScript performance?

**Keywords:** `DOM` · `Debounce` · `Cache`

Minimize DOM reads and writes, use debouncing or throttling for high-frequency handlers, and cache expensive computations when inputs repeat.

---

# TypeScript

## 1. What are the main differences between TypeScript and JavaScript?

**Keywords:** `Static Types` · `Compile Time` · `Tooling`

TypeScript is JavaScript with optional static typing. It catches many type errors at compile time, adds types, interfaces, enums, generics, and utility types, and compiles down to JavaScript.

---

## 2. What is the difference between `type`, `interface`, and `enum`?

**Keywords:** `Merge` · `Unions` · `Named Constants`

Interfaces can be extended and declaration-merged. `type` aliases can express unions, intersections, and more complex shapes. Enums define a set of named numeric or string constants.

---

## 3. How do unions and intersections work?

**Keywords:** `|` · `&` · `Combined Types`

A union (`A | B`) means a value can be one of several types. An intersection (`A & B`) combines types so a value must satisfy all of them.

---

## 4. How do deriving and narrowing types work?

**Keywords:** `Inference` · `Type Guards` · `Control Flow`

TypeScript infers types from initialization and usage. Narrowing refines a type inside branches using checks such as `typeof`, `instanceof`, or custom type guards.

---

## 5. What are `keyof` and `typeof` operators?

**Keywords:** `Keys Union` · `Type of Value` · `Generics`

`keyof T` produces a union of property names of type `T`. `typeof x` in type position gives the type of a variable or expression—useful for tying types to runtime values.

---

## 6. What are `Record`, `Partial`, `Pick`, and `Omit`?

**Keywords:** `Utility Types` · `Shape` · `Optional`

`Record<K, V>` maps keys `K` to values `V`. `Partial<T>` makes all properties of `T` optional. `Pick<T, K>` selects a subset of properties. `Omit<T, K>` removes properties from `T`.

---

## 7. What are generic types in TypeScript?

**Keywords:** `Type Parameter` · `Reusable` · `Type Safety`

Generics let you write functions and types that work across many types while keeping compile-time type safety—for example `function identity<T>(x: T): T`.

---

## 8. What is the `satisfies` operator?

**Keywords:** `Check Shape` · `Preserve Inference` · `Literal Types`

`satisfies` checks that a value matches a type without widening the inferred type of the value. Use it when you want validation plus precise literal inference.

---

## 9. What is `any` vs `unknown` vs `never`?

**Keywords:** `Escape Hatch` · `Safe Top` · `Uninhabited`

`any` turns off type checking for that value. `unknown` accepts any value but requires narrowing before use. `never` is the type of values that never occur (for example a function that always throws).

---

## 10. What are optional properties and `readonly`?

**Keywords:** `?` · `Immutable Field` · `Object Types`

Optional properties use `?` and may be absent. `readonly` marks properties that cannot be reassigned after the object is created (shallow immutability for that field).

---

## 11. How does TypeScript work with third-party JavaScript libraries?

**Keywords:** `.d.ts` · `DefinitelyTyped` · `@types`

Libraries without built-in types are described with declaration files (`.d.ts`). Community packages under `@types/*` or hand-written declarations supply types for plain JavaScript modules.
