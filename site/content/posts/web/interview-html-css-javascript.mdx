# HTML

## 1. What are semantic HTML elements, and why are they important?

**Keywords:** `semantic` · `meaning` · `header` · `nav` · `main` · `article` · `section` · `footer`

**Expectations:** Explain that semantic HTML elements describe their meaning clearly for both humans and machines, and name examples such as `<header>`, `<nav>`, `<main>`, `<article>`, `<section>`, and `<footer>`.

---

## 2. How do semantic elements improve accessibility?

**Keywords:** `screen readers` · `structure` · `purpose` · `a11y`

**Expectations:** Explain that when landmarks and semantic tags are used correctly, screen readers can better understand the structure and purpose of the page.

---

## 3. Inline vs inline-block vs block?

**Keywords:** `inline` · `no new line` · `block` · `new line` · `inline-block` · `width/height`

**Expectations:** Contrast the three: inline elements stay in the text flow and do not start on a new line, block elements start on a new line and take the full available width, and inline-block stays in flow like inline but allows setting width and height.

---

## 4. How do you improve accessibility on a website?

**Keywords:** `semantic HTML` · `alt text` · `labels` · `keyboard navigation` · `focus` · `color contrast` · `ARIA` · `testing`

**Expectations:** Start with semantic HTML and landmarks, meaningful `alt` text on images, and form inputs connected to `<label>` elements. Mention making everything usable with the keyboard with a visible focus state, keeping enough color contrast, and using ARIA only when native HTML can't express the behavior. Finish by explaining that you test with a screen reader and tools like Lighthouse or axe.

---

# CSS

## 1. How do you use CSS in a React project?

**Keywords:** `Tailwind CSS` · `utility-first` · `styling`

**Expectations:** Mention using Tailwind CSS for utility-first styling, so most UI can be built with small, composable classes in the markup.

---

## 2. Difference between Flexbox and Grid?

**Keywords:** `Flexbox` · `one-dimensional` · `Grid` · `two-dimensional`

**Expectations:** Contrast the two: Flexbox lays out items in one direction (row or column), while Grid lays out items in two dimensions (rows and columns).

---

## 3. What are the CSS `position` values?

**Keywords:** `static` · `relative` · `absolute` · `fixed` · `sticky`

**Expectations:** Name the common values `static`, `relative`, `absolute`, `fixed`, and `sticky`, and explain that each controls how an element is placed relative to the normal flow, a positioned ancestor, or the viewport.

---

## 4. `display: none` vs `visibility: hidden`?

**Keywords:** `display: none` · `remove from layout` · `visibility: hidden` · `hide but keep space`

**Expectations:** Contrast them: `display: none` removes the element from the layout, while `visibility: hidden` hides it visually but still reserves its space.

---

## 5. What are CSS pre-processors?

**Keywords:** `Sass` · `Less` · `variables` · `nesting` · `mixins` · `functions`

**Expectations:** Name pre-processors like Sass and Less, and explain that they extend CSS with variables, nesting, mixins, and functions to make styles more modular and reusable.

---

## 6. When would you use a pre-processor?

**Keywords:** `large projects` · `modular` · `maintainable` · `reusable`

**Expectations:** Explain that you'd use a pre-processor on larger projects that need modular, maintainable, and reusable stylesheets.

---

## 7. What is Tailwind CSS?

**Keywords:** `utility-first` · `CSS framework` · `small classes`

**Expectations:** Define Tailwind CSS as a utility-first CSS framework that builds UI from small, single-purpose classes.

---

## 8. When would you choose Tailwind over SCSS or CSS Modules?

**Keywords:** `rapid development` · `consistent design` · `less CSS bloat`

**Expectations:** Explain that you'd choose Tailwind when you want faster UI work, consistent design tokens, and less custom CSS to maintain.

---

## 9. What does utility-first mean?

**Keywords:** `single-purpose classes` · `compose in markup`

**Expectations:** Explain that a utility-first approach builds components by composing small utility classes directly in the markup, instead of writing large custom CSS rules first.

---

## 10. How does Tailwind handle responsive design?

**Keywords:** `mobile-first` · `breakpoints` · `responsive prefixes`

**Expectations:** Explain that Tailwind uses mobile-first breakpoints, so styles scale up with prefixes like `sm:`, `md:`, and `lg:`.

---

## 11. How does dark mode work in Tailwind?

**Keywords:** `dark class` · `root element` · `variant`

**Expectations:** Explain that dark mode is typically enabled by adding a `dark` class on a root element and using `dark:` variants for alternate styles.

---

## 12. What is `@apply`, and when should you use it?

**Keywords:** `@apply` · `compose utilities` · `custom class` · `use sparingly`

**Expectations:** Explain that `@apply` lets you compose utility classes into a custom CSS class. Point out that you should prefer utilities in markup first and use `@apply` sparingly, when a repeated pattern needs a named class.

---

# JavaScript

## 1. What is a closure in JavaScript?

**Keywords:** `Function` · `Lexical Scope` · `Remember Variables`

**Expectations:** Define a closure as a function that remembers and can access variables from its enclosing scope, even after that outer function has finished running.

---

## 2. What is hoisting?

**Keywords:** `Declarations` · `Top of Scope` · `TDZ`

**Expectations:** Explain that hoisting moves variable and function declarations to the top of their scope during compilation. Contrast `var`, which is hoisted and initialized as `undefined`, with `let` and `const`, which are hoisted but sit in the temporal dead zone until their declaration line runs.

---

## 3. How does scope work in JavaScript?

**Keywords:** `Global` · `Function` · `Block`

**Expectations:** Name the three kinds of scope in JavaScript: global scope, function scope, and block scope (for `let` and `const`).

---

## 4. What is the difference between `var`, `let`, and `const`?

**Keywords:** `Function-scoped` · `Block-scoped` · `Reassignment`

**Expectations:** Contrast the three: `var` is function-scoped and can be redeclared, `let` is block-scoped and cannot be redeclared in the same scope, and `const` is block-scoped and cannot be reassigned after initialization.

---

## 5. How does `this` work in JavaScript?

**Keywords:** `Call Site` · `Context` · `Binding`

**Expectations:** Explain that the value of `this` depends on how the function is called, not where it is defined.

---

## 6. What is the difference between `call`, `apply`, and `bind`?

**Keywords:** `Invoke` · `Arguments` · `Fixed this`

**Expectations:** Contrast the three: `call` invokes a function with a given `this` and arguments listed individually, `apply` invokes it with arguments as an array, and `bind` returns a new function with `this` permanently bound.

---

## 7. What happens when you use `new` with a function?

**Keywords:** `Object` · `Prototype` · `Constructor`

**Expectations:** Walk through the steps: `new` creates a new object, sets its prototype, binds `this` to that object, runs the function body, and returns the object (unless the constructor explicitly returns something else).

---

## 8. What is the JavaScript event loop?

**Keywords:** `Call Stack` · `Tasks` · `Non-blocking`

**Expectations:** Explain that the event loop coordinates running synchronous code on the call stack, then draining microtasks, then macrotasks, so JavaScript can stay responsive while handling async work.

---

## 9. What are microtasks vs macrotasks?

**Keywords:** `Promises` · `setTimeout` · `Order`

**Expectations:** Explain that microtasks (for example Promise callbacks) run before the next macrotask (for example `setTimeout` callbacks), and point out that this ordering affects when async code runs relative to timers and I/O.

---

## 10. What are common async patterns?

**Keywords:** `Callbacks` · `Promises` · `async/await`

**Expectations:** Name the common patterns: callbacks, Promises (chaining and `Promise.all`), and `async/await` for writing asynchronous code in a more synchronous style.

---

## 11. What is the difference between `setTimeout` and `setInterval`?

**Keywords:** `Once` · `Repeat` · `Delay`

**Expectations:** Contrast them: `setTimeout` runs a callback once after a delay, while `setInterval` runs a callback repeatedly on a fixed interval until cleared.

---

## 12. What is prototype inheritance?

**Keywords:** `Prototype Chain` · `Objects` · `Lookup`

**Expectations:** Explain that objects inherit properties and methods from their prototype via the prototype chain, and that when a property is missing on the object, JavaScript looks it up the chain.

---

## 13. What is the difference between `==` and `===`?

**Keywords:** `Coercion` · `Strict` · `Type`

**Expectations:** Contrast them: `==` compares with type coercion when types differ, while `===` is strict equality with no coercion, so type and value must match.

---

## 14. What is the difference between `null` and `undefined`?

**Keywords:** `No Value` · `Unassigned` · `Intentional`

**Expectations:** Contrast them: `null` is an assigned value meaning “no value” (often intentional), while `undefined` means a variable was declared but not assigned, or a property is missing.

---

## 15. What are JavaScript data types?

**Keywords:** `Primitive` · `Object` · `typeof`

**Expectations:** Name the primitives (string, number, boolean, null, undefined, symbol, and bigint) and the non-primitive object type, pointing out that arrays and functions are objects too.

---

## 16. Shallow copy vs deep copy?

**Keywords:** `Reference` · `Nested Objects` · `Clone`

**Expectations:** Contrast them: a shallow copy duplicates the top level but keeps references to nested objects, while a deep copy recursively clones nested structures so the copies are independent.

---

## 17. What is immutability?

**Keywords:** `No Mutation` · `New Data` · `Predictable State`

**Expectations:** Define immutability as not changing existing data in place and creating new data instead. Explain that this makes state updates easier to reason about and debug.

---

## 18. What is event delegation?

**Keywords:** `Bubbling` · `Parent Listener` · `Dynamic Children`

**Expectations:** Explain that event delegation attaches one listener on a parent and handles events from children using event bubbling. Mention that it works well for lists and dynamically added elements.

---

## 19. How do you stop event propagation?

**Keywords:** `stopPropagation` · `Bubbling` · `Capture`

**Expectations:** Explain that you call `event.stopPropagation()` on the event object to prevent the event from bubbling (or capturing) to ancestor elements.

---

## 20. What is a memory leak in JavaScript?

**Keywords:** `Unreachable` · `Retained` · `Heap`

**Expectations:** Define a memory leak as memory that is no longer needed but stays allocated because something still holds a reference to it.

---

## 21. What are common causes of memory leaks?

**Keywords:** `Listeners` · `Timers` · `Closures`

**Expectations:** Name the common causes: event listeners that are never removed, timers that are never cleared, and closures that keep large objects alive longer than necessary.

---

## 22. How can you prevent memory leaks?

**Keywords:** `Cleanup` · `removeEventListener` · `clearTimeout`

**Expectations:** Explain that you remove event listeners when components or nodes are destroyed, clear timers and intervals, and avoid keeping unnecessary references in globals or long-lived closures.

---

## 23. What is garbage collection?

**Keywords:** `Reachability` · `Automatic` · `GC`

**Expectations:** Define garbage collection as automatic memory management, where the runtime frees objects that are no longer reachable from the root set (globals, active stack, etc.).

---

## 24. How do you improve JavaScript performance?

**Keywords:** `DOM` · `Debounce` · `Cache`

**Expectations:** Mention minimizing DOM reads and writes, using debouncing or throttling for high-frequency handlers, and caching expensive computations when inputs repeat.

---

# TypeScript

## 1. What are the main differences between TypeScript and JavaScript?

**Keywords:** `Static Types` · `Compile Time` · `Tooling`

**Expectations:** Explain that TypeScript is JavaScript with optional static typing that catches many type errors at compile time. Mention that it adds types, interfaces, enums, generics, and utility types, and compiles down to JavaScript.

---

## 2. What is the difference between `type`, `interface`, and `enum`?

**Keywords:** `Merge` · `Unions` · `Named Constants`

**Expectations:** Contrast the three: interfaces can be extended and declaration-merged; `type` aliases can express unions, intersections, and more complex shapes; and enums define a set of named numeric or string constants.

---

## 3. How do unions and intersections work?

**Keywords:** `|` · `&` · `Combined Types`

**Expectations:** Explain that a union (`A | B`) means a value can be one of several types, while an intersection (`A & B`) combines types so a value must satisfy all of them.

---

## 4. How do deriving and narrowing types work?

**Keywords:** `Inference` · `Type Guards` · `Control Flow`

**Expectations:** Explain that TypeScript infers types from initialization and usage, and that narrowing refines a type inside branches using checks such as `typeof`, `instanceof`, or custom type guards.

---

## 5. What are `keyof` and `typeof` operators?

**Keywords:** `Keys Union` · `Type of Value` · `Generics`

**Expectations:** Explain that `keyof T` produces a union of property names of type `T`, and that `typeof x` in type position gives the type of a variable or expression, which is useful for tying types to runtime values.

---

## 6. What are `Record`, `Partial`, `Pick`, and `Omit`?

**Keywords:** `Utility Types` · `Shape` · `Optional`

**Expectations:** Define each utility type: `Record<K, V>` maps keys `K` to values `V`, `Partial<T>` makes all properties of `T` optional, `Pick<T, K>` selects a subset of properties, and `Omit<T, K>` removes properties from `T`.

---

## 7. What are generic types in TypeScript?

**Keywords:** `Type Parameter` · `Reusable` · `Type Safety`

**Expectations:** Explain that generics let you write functions and types that work across many types while keeping compile-time type safety, and give an example such as `function identity<T>(x: T): T`.

---

## 8. What is the `satisfies` operator?

**Keywords:** `Check Shape` · `Preserve Inference` · `Literal Types`

**Expectations:** Explain that `satisfies` checks that a value matches a type without widening the inferred type of the value. Mention using it when you want validation plus precise literal inference.

---

## 9. What is `any` vs `unknown` vs `never`?

**Keywords:** `Escape Hatch` · `Safe Top` · `Uninhabited`

**Expectations:** Contrast the three: `any` turns off type checking for that value; `unknown` accepts any value but requires narrowing before use; and `never` is the type of values that never occur (for example a function that always throws).

---

## 10. What are optional properties and `readonly`?

**Keywords:** `?` · `Immutable Field` · `Object Types`

**Expectations:** Explain that optional properties use `?` and may be absent, while `readonly` marks properties that cannot be reassigned after the object is created (shallow immutability for that field).

---

## 11. How does TypeScript work with third-party JavaScript libraries?

**Keywords:** `.d.ts` · `DefinitelyTyped` · `@types`

**Expectations:** Explain that libraries without built-in types are described with declaration files (`.d.ts`), and mention that community packages under `@types/*` or hand-written declarations supply types for plain JavaScript modules.
