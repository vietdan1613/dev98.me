## 1. What is Python?

**Expectations:** Readable · Interpreted · Dynamic typing · Libraries · Cross-platform

**Example answer:**

> Python is a high-level, general-purpose programming language known for its readable syntax and broad use in web development, automation, data science, and AI.
>

>
> - **Simple, readable syntax**, which makes it approachable for beginners and productive for experienced developers.

## 2. List vs Tuple

**Expectations:** Mutable · Immutable · Memory · Performance

**Example answer:**

> Lists and tuples are both ordered sequences, but they differ in mutability.
>
> A **list** is mutable, so I can add, remove, or change elements after creation. It has more built-in methods, such as `append()`, `remove()`, and `sort()`, and it uses a bit more memory.
>
> A **tuple** is immutable, so its elements cannot change after creation. It uses less memory, is slightly faster to iterate, and can be used as a dictionary key when all its elements are hashable. I use tuples for fixed records, such as coordinates, and lists for collections that change.

```python
colors = ["red", "green"]
colors.append("blue")
print(colors)  # ['red', 'green', 'blue']

point = (3, 4)
point[0] = 5  # TypeError: 'tuple' object does not support item assignment
```

## 3. What is `__init__()`?

**Expectations:** Constructor · Initialize · Object

**Example answer:**

> `__init__()` is the method Python calls automatically after a new instance of a class is created. It is often called the constructor, although technically `__new__()` creates the object and `__init__()` initializes it.

> I use it to assign initial values to the object's attributes and run any setup the object needs.

```python
class BookShop:

b = BookShop("Sandman")
b.book()  # The title of the book is Sandman
```

## 4. Mutable vs Immutable

**Expectations:** Mutable = can change · Immutable = cannot change

**Example answer:**

> Mutable objects can be changed after creation. Examples are `list`, `dict`, and `set`: I can add, remove, or update elements in place, which suits collections that change often.
>
> Immutable objects cannot be changed after creation. Examples are `int`, `float`, `str`, `tuple`, and `frozenset`. Any operation that looks like a modification actually creates a new object.
>
> A common trap is that reassigning a variable is not mutation. `name = "world"` just points the name at a new string object; the old string was never changed.

```python
nums = [1, 2, 3]
nums.append(4)        # the same list object is modified
print(nums)           # [1, 2, 3, 4]

text = "hello"
upper = text.upper()  # returns a new string
print(text)           # hello

point = (1, 2, 3)
point[0] = 4          # TypeError
```

## 5. What is Comprehension?

**Expectations:** One-line · List · Dictionary · Generator

**Example answer:**

> A comprehension is a concise way to build a new collection from an iterable in a single expression, instead of writing a multi-line `for` loop.
>
> A **list comprehension** uses square brackets, and a **dictionary comprehension** uses curly braces with `key: value` pairs.
>
> There is no tuple comprehension. Parentheses create a **generator expression**, which produces values lazily. To get a tuple, I pass a generator to `tuple()`.

```python
squares = [i ** 2 for i in range(1, 6)]
# [1, 4, 9, 16, 25]

square_map = {i: i ** 2 for i in range(1, 6)}
# {1: 1, 2: 4, 3: 9, 4: 16, 5: 25}

gen = (i for i in range(1, 6))
# <generator object <genexpr> ...>

numbers = tuple(i for i in range(1, 6))
# (1, 2, 3, 4, 5)
```

## 6. What is the GIL?

**Expectations:** CPython · One thread · CPU-bound · I/O-bound

**Example answer:**

> The Global Interpreter Lock is a mutex in CPython, the reference Python implementation, that allows only one native thread to execute Python bytecode at a time.
>
> It simplifies memory management by protecting internal state such as reference counts, but it prevents true parallelism for CPU-bound work in threads. For I/O-bound work, threads still help, because they release the GIL while waiting on the network, files, or a database.
>
> For CPU-bound work, I would use `multiprocessing` or libraries that do heavy work in C outside the GIL, such as NumPy. Python 3.13 added an experimental free-threaded build without the GIL (PEP 703), and Python 3.14 makes it officially supported, though some C extensions are not yet compatible.

## 7. Common Searching and Graph Algorithms

**Expectations:** Binary search · BFS · DFS · A\* · AVL tree

**Example answer:**

> - **Binary search** finds an item in a sorted list by repeatedly halving the search range, in O(log n) time. In Python, the `bisect` module implements it.
> - **An AVL tree** is a self-balancing binary search tree. It rebalances after inserts and deletes, so searches stay O(log n).
> - **Breadth-first search (BFS)** explores a graph level by level, usually with a `collections.deque` queue. It finds the shortest path in an unweighted graph.
> - **Depth-first search (DFS)** goes as deep as possible down one branch before backtracking, using recursion or a stack. It suits maze solving, cycle detection, and tree traversal.
> - **A\* search** finds the shortest path by combining the cost so far with a heuristic estimate of the remaining distance. It is common in maps and games.

```python
from collections import deque

def bfs(graph, start):
    visited = {start}
    queue = deque([start])
    order = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append(neighbor)
    return order
```

## 8. What is a `KeyError`?

**Expectations:** Missing key · `.get()` · `try/except` · `in`

**Example answer:**

> A `KeyError` is raised when I access a dictionary key that does not exist, for example looking up a student who isn't in a dictionary of scores.

```python
    print(scores["bob"])
```

## 9. How Does Python Manage Memory?

**Expectations:** Private heap · Reference counting · Garbage collection

**Example answer:**

> Python manages memory automatically. All objects live in a private heap, and the memory manager handles allocation and deallocation.
>
> CPython mainly uses **reference counting**: each object tracks how many references point to it, and when the count drops to zero, its memory is freed immediately. Reference counting cannot free objects that reference each other in a cycle, so a **cyclic garbage collector** periodically finds and collects those.
>
> The `gc` module lets me interact with the collector, for example to run a collection with `gc.collect()` or disable it temporarily.

## 10. Shallow Copy vs Deep Copy

**Expectations:** Reference · Nested objects · Independent copy

**Example answer:**

> A **shallow copy** creates a new outer object but fills it with references to the same inner objects. If the original contains nested mutable objects, such as lists inside a list, a change to an inner object shows up in both. I create one with `list.copy()`, slicing, or `copy.copy()`.
>
> A **deep copy** recursively copies every nested object, so the result is fully independent. I create one with `copy.deepcopy()`.
>
> I use a shallow copy when the contents are immutable or when sharing nested objects is intended, and a deep copy for nested structures I want to modify independently.

```python
import copy

original = [[1, 2], [3, 4]]
shallow = copy.copy(original)
deep = copy.deepcopy(original)

original[0].append(99)
print(shallow)  # [[1, 2, 99], [3, 4]]
print(deep)     # [[1, 2], [3, 4]]
```

**Example answer:**

## 12. What is Monkey Patching?

**Expectations:** Runtime · Modify behavior · Class · Module

**Example answer:**

> Monkey patching means changing the behavior of a class or module at runtime, for example by replacing one of its methods with another function.
>
> It is most useful in tests, to replace a slow or external dependency. I use it sparingly in application code, because it makes behavior harder to follow and can surprise other developers. In tests, I prefer `unittest.mock.patch` or pytest's `monkeypatch` fixture, which undo the change automatically.

```python
class Monkey:
    def patch(self):
        print("patch() is being called")


def monk_p(self):
    print("monk_p() is being called")


Monkey.patch = monk_p

Monkey().patch()  # monk_p() is being called
```

## 13. What is the `with` Statement?

**Expectations:** Resource management · Cleanup · File

**Example answer:**

> The `with` statement is designed for resource management. It uses a context manager to set up a resource and guarantee cleanup when the block ends, even if an exception is raised.
>
> The common example is files: instead of writing `open`, `try`, `finally`, and `close`, I use `with open(...)`, and the file is closed automatically. The same pattern works for locks, database connections, and transactions.

```python
with open("myfile.txt", "w") as file:
    file.write("Hello, world!")
# the file is closed here
```

## 14. Why Use `else` with `try/except`?

**Expectations:** No exception · Success

**Example answer:**

> The `else` block runs only when the `try` block finishes without raising an exception.
>
> It keeps the `try` block small: only the code that might fail goes in `try`, and the follow-up code for the success case goes in `else`. That way, I don't accidentally catch exceptions from code I didn't mean to protect.
>
> In this example, entering `2` and `d` triggers the `except` block, while entering `2` and `1` prints the result from the `else` block.

```python
try:
    num1 = int(input("Enter Numerator: "))
    num2 = int(input("Enter Denominator: "))
    division = num1 / num2
except (ValueError, ZeroDivisionError):
    print("Invalid input!")
else:
    print(f"Result is: {division}")
    print("Division is successful.")
```

## 15. What are Decorators?

**Expectations:** Wrapper · Extend behavior · `@decorator`

**Example answer:**

> A decorator is a function that takes another function and returns a new function that adds behavior around it, without changing the original function's code. The `@decorator` syntax applies it.
>
> Common uses are logging, authentication checks, caching, retries, and timing. I use `functools.wraps` inside the wrapper so the decorated function keeps its original name and docstring.

```python
import functools

def my_decorator(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        print("Something is happening before the function is called.")
        result = func(*args, **kwargs)
        print("Something is happening after the function is called.")
        return result
    return wrapper

@my_decorator
def say_hello():
    print("Hello!")

say_hello()
# Something is happening before the function is called.
# Hello!
# Something is happening after the function is called.
```

## 16. What are Context Managers?

**Expectations:** `__enter__` · `__exit__` · `with` · Resource

**Example answer:**

> A context manager controls how a resource is acquired and released. When a `with` block starts, Python calls `__enter__()`, and its return value is bound to the name after `as`. When the block ends, even because of an exception, Python calls `__exit__()` to clean up.
>
> I can implement one as a class with those two methods, or more simply with the `contextlib.contextmanager` decorator on a generator function.

```python
class FileManager:
    def __init__(self, filename, mode):
        self.filename = filename
        self.mode = mode

    def __enter__(self):
        self.file = open(self.filename, self.mode)
        return self.file

    def __exit__(self, exc_type, exc_value, traceback):
        self.file.close()


with FileManager("test.txt", "w") as f:
    f.write("Hello, world!")
```

```python
from contextlib import contextmanager

@contextmanager
def file_manager(filename, mode):
    file = open(filename, mode)
    try:
        yield file
    finally:
        file.close()
```

## 17. What are Metaclasses?

**Expectations:** Class of classes · `type` · Create classes

**Example answer:**

> A metaclass is the class of a class. A regular class creates objects, and a metaclass creates classes. The default metaclass is `type`.
>
> With a custom metaclass, I can modify a class definition when it is created, for example to enforce naming rules, register classes automatically, or add methods. In practice, class decorators or `__init_subclass__` are often simpler, so I reach for metaclasses mainly in framework-level code.

```python
class Meta(type):
    def __new__(cls, name, bases, dct):
        print(f"Creating class {name}")
        return super().__new__(cls, name, bases, dct)


class MyClass(metaclass=Meta):
    pass
# Creating class MyClass
```

## 20. How Do You Handle Missing Values?

**Expectations:** `isnull()` · `dropna()` · `fillna()` · `replace()` · `interpolate()`

**Example answer:**

> First, I identify missing values with `df.isnull().sum()`, which counts the missing values in each column.
>
> Then I choose a strategy based on the data:
>
> - Drop rows or columns with `dropna()`, but only when a small share of a large dataset is missing, because dropping loses information.
> - Fill with a constant, the mean or median, or neighboring values using `fillna()`, `ffill()`, or `bfill()`.
> - Replace a specific marker value with `replace()`.
> - Estimate values from their neighbors with `interpolate()`, which works well for time series.

```python
import numpy as np
import pandas as pd

df = pd.DataFrame({
    "id": [1, 4, np.nan, 9],
    "age": [30, 45, np.nan, np.nan],
    "score": [np.nan, 140, 180, 198],
})

df.isnull().sum()
# id       1
# age      2
# score    1

df.dropna(axis=0, how="any")
df.fillna(df.mean())
df.bfill()
df.replace(to_replace=np.nan, value=-999)
df.interpolate(method="linear", limit_direction="forward")
```

## 22. Normalization vs Standardization

**Expectations:** Normalization → 0–1 · Standardization → mean 0, std 1

**Example answer:**

> **Normalization** rescales values into a fixed range, usually `[0, 1]`, using the minimum and maximum. **Standardization** transforms values to have a mean of `0` and a standard deviation of `1`.
>
> Many machine learning models, such as k-nearest neighbors, SVMs, and models trained with gradient descent, work better when features are on similar scales. I use normalization when I need bounded values, and standardization when the data has outliers that would distort min-max scaling. I fit the scaler on the training data only and then apply it to the test data, to avoid data leakage.

```python
import numpy as np
from sklearn.preprocessing import MinMaxScaler, StandardScaler

data = np.array([[1, 2], [3, 4], [5, 6]])

normalized = MinMaxScaler().fit_transform(data)
standardized = StandardScaler().fit_transform(data)
```

## 24. Check if a Number is a Perfect Square

**Expectations:** `math.isqrt()` · Square

**Example answer:**

> I use `math.isqrt(num)` to get the exact integer square root, square it, and check whether the result equals the original number. Using `isqrt` avoids the floating-point errors that `math.sqrt` can have with large numbers.
>
> For `10`, the integer square root is `3`, and `3 * 3 = 9`, so it returns `False`. For `36`, the root is `6`, and `6 * 6 = 36`, so it returns `True`.

```python
import math

def valid_square(num):
    if num < 0:
        return False
    root = math.isqrt(num)
    return root * root == num

valid_square(10)  # False
valid_square(36)  # True
```

## 25. Count Trailing Zeros in `n!`

**Expectations:** Factorial · Trailing zeros · Factors of 5

**Example answer:**

> The straightforward approach is to calculate `n!`, convert it to a string, and count the zeros from the right. For example, `7! = 5040` has two zeros in total but only one trailing zero, so the answer is `1`.
>
> That works for small `n`, but factorials grow very fast. The better approach is to notice that each trailing zero comes from a factor of 10, which is `2 × 5`, and factors of 2 are always more common. So I count the factors of 5 in `n!`: `n // 5 + n // 25 + n // 125 + ...`. That runs in O(log n) time.

```python
import math

def factorial_trailing_zeros_naive(n):
    digits = str(math.factorial(n))
    return len(digits) - len(digits.rstrip("0"))

def factorial_trailing_zeros(n):
    count = 0
    while n >= 5:
        n //= 5
        count += n
    return count

factorial_trailing_zeros(10)  # 2
factorial_trailing_zeros(18)  # 3
```

## 26. Can a String Be Split into Dictionary Words?

**Expectations:** Recursion · String segmentation · Memoization

**Example answer:**

> I try every split point. If the prefix `s[:i]` is a dictionary word, I recursively check whether the rest of the string, `s[i:]`, can also be segmented. An empty remainder means the whole string was split successfully.
>
> Without caching, the same suffixes get checked again and again, which is exponential in the worst case. With **memoization**, each suffix is solved only once, which brings the work down to polynomial time. I also store the dictionary as a set for O(1) lookups.
>
> For example, `"applepie"` with the words `apple`, `pie`, `pen`, and `app` returns `True`.

```python
def can_segment_str(s, words, memo=None):
    if memo is None:
        memo = {}
    if not s:
        return True
    if s in memo:
        return memo[s]

    for i in range(1, len(s) + 1):
        if s[:i] in words and can_segment_str(s[i:], words, memo):
            memo[s] = True
            return True

    memo[s] = False
    return False

can_segment_str("applepie", {"apple", "pie", "pen", "app"})
# True
```

## 27. Remove Duplicates from a Sorted Array

**Expectations:** Sorted · In-place · Two pointers

**Example answer:**

> Because the array is sorted, duplicates sit next to each other. I use two pointers: `i` scans the array, and `insert_index` marks where the next unique value goes. Whenever `array[i]` differs from the previous element, I write it at `insert_index` and move `insert_index` forward.
>
> At the end, `insert_index` is `k`, the number of unique elements, and `array[:k]` holds them. This is O(n) time and O(1) extra space. For example, `[1, 1, 2, 3, 3]` returns `3`.

```python
def remove_duplicates(array):
    if not array:
        return 0
    insert_index = 1
    for i in range(1, len(array)):
        if array[i - 1] != array[i]:
            array[insert_index] = array[i]
            insert_index += 1
    return insert_index

array = [1, 2, 2, 3, 3, 4]
k = remove_duplicates(array)
# k = 4, array[:k] -> [1, 2, 3, 4]
```

## 28. Find the Missing Number

**Expectations:** Expected sum · Actual sum · Difference

**Example answer:**

> The list contains the numbers from `1` to `n` with exactly one missing, so `n` is the list length plus one. I calculate the expected sum with the arithmetic series formula `n * (n + 1) // 2`, subtract the actual sum of the list, and the difference is the missing number.
>
> For example, `[4, 5, 3, 2, 8, 1, 6]` has `n = 8`, and the missing number is `7`. This is O(n) time and O(1) space.

```python
def find_missing(nums):
    n = len(nums) + 1
    expected_sum = n * (n + 1) // 2
    return expected_sum - sum(nums)

find_missing([4, 5, 3, 2, 8, 1, 6])  # 7
find_missing([1, 5, 6, 3, 4])        # 2
```

## 29. Check if a String is a Palindrome

**Expectations:** Reverse · Normalize

**Example answer:**

> A palindrome reads the same forward and backward. I first normalize the string by keeping only letters and digits and converting it to lowercase, then compare it with its reverse using `s[::-1]`.
>
> This is O(n) time and O(n) space for the cleaned and reversed copies. If memory matters, I can compare characters with two pointers from both ends for O(1) extra space.

```python
def is_palindrome(s):
    s = "".join(ch for ch in s if ch.isalnum()).lower()
    return s == s[::-1]

is_palindrome("A man, a plan, a canal: Panama")  # True
is_palindrome("hello")                           # False
```

## 30. Maximum Single Stock Profit

**Expectations:** Minimum price · Current profit · Max profit

**Example answer:**

> I make one pass over the prices while tracking the lowest buy price seen so far and the best profit. For each price, I calculate the profit of selling at that price after buying at the lowest earlier price. If it beats the best profit, I record this price as the sell price. Then I update the lowest buy price if the current price is lower.
>
> I start the best profit as the difference between the first two prices, so if prices only fall, the function still returns the smallest loss. At the end, the buy price is the sell price minus the best profit. This is O(n) time and O(1) space.
>
> For example, `[8, 4, 12, 9, 20, 1]` returns buy `4` and sell `20`, and `[8, 6, 5, 4, 3, 2, 1]` returns buy `6` and sell `5`.

```python
def buy_sell_stock_prices(prices):
    current_buy = prices[0]
    global_sell = prices[1]
    global_profit = global_sell - current_buy

    for i in range(1, len(prices)):
        current_profit = prices[i] - current_buy

        if current_profit > global_profit:
            global_profit = current_profit
            global_sell = prices[i]

        if current_buy > prices[i]:
            current_buy = prices[i]

    return global_sell - global_profit, global_sell

buy_sell_stock_prices([8, 4, 12, 9, 20, 1])   # (4, 20)
buy_sell_stock_prices([8, 6, 5, 4, 3, 2, 1])  # (6, 5)
```

## 31. Find a Pythagorean Triplet

**Expectations:** a² + b² = c² · Square · Sort · Set

**Example answer:**

> I square every element and sort the squares. For each candidate `c²`, starting from the largest, I scan the smaller squares and keep a set of the values seen so far. If `c² - b²` is already in the set, then some `a² + b² = c²`, so a triplet exists.
>
> This is O(n²) time and O(n) space for the set. For example, `[3, 1, 4, 6, 5]` returns `True` because `3² + 4² = 5²`, and `[10, 4, 6, 12, 5]` returns `False`.

```python
def check_triplet(nums):
    squares = sorted(x * x for x in nums)
    n = len(squares)

    for i in range(n - 1, 1, -1):
        seen = set()
        for j in range(i - 1, -1, -1):
            if squares[i] - squares[j] in seen:
                return True
            seen.add(squares[j])
    return False

check_triplet([3, 1, 4, 6, 5])    # True
check_triplet([10, 4, 6, 12, 5])  # False
```

## 32. Coin Change

**Expectations:** Dynamic programming · DP array

**Example answer:**

> This is a dynamic programming problem. I create a list `solution` of size `amount + 1`, where `solution[i]` is the number of ways to make amount `i`. I set `solution[0] = 1`, because there is exactly one way to make zero: use no coins.
>
> Then, for each coin, I loop from the coin's value up to the amount and add `solution[i - coin]` to `solution[i]`. Putting the coins in the outer loop counts combinations rather than orderings. The answer is `solution[amount]`.
>
> For coins `[1, 2, 5]` and amount `5`, there are four ways. This is O(amount × number of coins) time and O(amount) space.

```python
def solve_coin_change(denominations, amount):
    solution = [0] * (amount + 1)
    solution[0] = 1
    for coin in denominations:
        for i in range(coin, amount + 1):
            solution[i] += solution[i - coin]
    return solution[amount]

solve_coin_change([1, 2, 5], 5)  # 4
```

## 33. Lambda vs Iterator vs Generator

**Expectations:** Lambda → anonymous · Iterator → iterate · Generator → `yield`

**Example answer:**

> A **lambda** is an anonymous function written in one line. It can take any number of arguments but contains a single expression, whose value is returned. I use it for short functions passed to `sorted()`, `map()`, or `filter()`.
>
> An **iterator** is an object that returns values one at a time. It implements `__iter__()` and `__next__()`, and raises `StopIteration` when it runs out. Lists, dictionaries, tuples, and sets are iterables: calling `iter()` on them returns an iterator.
>
> A **generator** is a function that uses `yield` instead of `return`. Calling it returns an iterator that produces values lazily, pausing at each `yield`, which saves memory for large or infinite sequences.

```python
square = lambda x: x * x
square(4)  # 16

it = iter([1, 2, 3])
next(it)   # 1
next(it)   # 2

def count_up(n):
    for i in range(n):
        yield i

list(count_up(3))  # [0, 1, 2]
```

## 34. Maximum `j - i`

**Expectations:** `arr[j] > arr[i]` · Index difference · Maximum

**Example answer:**

> The goal is to find indexes `i` and `j` where `arr[j] > arr[i]` and `j - i` is as large as possible.
>
> The brute-force solution uses two loops: for each `i` from the left, scan `j` from the right end and stop at the first `arr[j] > arr[i]`, since that gives the largest gap for this `i`. This is O(n²) time and O(1) space.
>
> To get O(n) time, I build a prefix-minimum array and a suffix-maximum array, then walk both with two pointers. For example, `[20, 70, 40, 50, 12, 38, 98]` returns `6`, with `i = 0` and `j = 6`.

```python
def max_index_diff(arr):
    n = len(arr)
    max_diff = -1
    for i in range(n):
        for j in range(n - 1, i, -1):
            if arr[j] > arr[i]:
                max_diff = max(max_diff, j - i)
                break
    return max_diff

def max_index_diff_linear(arr):
    n = len(arr)
    left_min = [arr[0]] * n
    for i in range(1, n):
        left_min[i] = min(left_min[i - 1], arr[i])

    right_max = [arr[-1]] * n
    for j in range(n - 2, -1, -1):
        right_max[j] = max(right_max[j + 1], arr[j])

    i = j = 0
    max_diff = -1
    while i < n and j < n:
        if left_min[i] < right_max[j]:
            max_diff = max(max_diff, j - i)
            j += 1
        else:
            i += 1
    return max_diff

max_index_diff([20, 70, 40, 50, 12, 38, 98])                 # 6
max_index_diff_linear([10, 3, 2, 4, 5, 6, 7, 8, 18, 0])      # 8
```

## 36. How Do You Implement an LRU Cache?

**Expectations:** LRU · `lru_cache` · `OrderedDict`

**Example answer:**

> The simplest option is the built-in `functools.lru_cache` decorator, which caches a function's results and evicts the least recently used entry once `maxsize` is reached.
>
> For a manual implementation, I use `OrderedDict`. On `get`, I move the key to the end to mark it as recently used. On `put`, I insert or update the key, move it to the end, and if the cache is over capacity, remove the oldest item with `popitem(last=False)`. Both operations are O(1).

```python
from functools import lru_cache

@lru_cache(maxsize=3)
def add(a, b):
    return a + b

add(1, 2)  # calculated and cached
add(1, 2)  # returned from the cache
```

```python
from collections import OrderedDict

class LRUCache:
    def __init__(self, capacity):
        self.capacity = capacity
        self.cache = OrderedDict()

    def get(self, key):
        if key not in self.cache:
            return None
        self.cache.move_to_end(key)
        return self.cache[key]

    def put(self, key, value):
        self.cache[key] = value
        self.cache.move_to_end(key)
        if len(self.cache) > self.capacity:
            self.cache.popitem(last=False)
```

## 38. What is RAG?

**Expectations:** Retrieval · Vector database · Context · Generation

**Example answer:**

> RAG stands for Retrieval-Augmented Generation. Instead of relying only on what the LLM learned during training, the system retrieves relevant documents from a knowledge base and passes them to the LLM as context. This makes answers more accurate and up to date, reduces hallucinations, and lets me use private data without retraining the model.
>
> It has three main parts: a **document store**, usually a vector database such as Pinecone, Chroma, or FAISS, that holds embedded documents; a **retriever** that finds the documents most similar to the query; and a **generator**, the LLM that writes the answer from the retrieved context.

```text
User Query
    ↓
Retriever
    ↓
Relevant Documents
    ↓
LLM
    ↓
Answer
```

```python
from langchain_chroma import Chroma
from langchain_openai import ChatOpenAI, OpenAIEmbeddings

vectorstore = Chroma.from_documents(documents, OpenAIEmbeddings())
llm = ChatOpenAI(model="gpt-5")

question = "What are Python best practices?"
docs = vectorstore.similarity_search(question, k=4)
context = "\n\n".join(doc.page_content for doc in docs)

answer = llm.invoke(
    f"Answer using only this context:\n{context}\n\nQuestion: {question}"
)
print(answer.content)
```

## 39. How Does `async/await` Work?

**Expectations:** `asyncio` · Non-blocking I/O · Concurrency · `gather`

**Example answer:**

> `async/await` lets one thread handle many I/O-bound tasks concurrently. When a coroutine reaches `await` on a network call, the `asyncio` event loop switches to another task instead of blocking.
>
> This matters in AI applications because LLM and API calls spend most of their time waiting. With `asyncio.gather()`, I can send several requests at once, so the total time is close to the slowest request instead of the sum of all of them. For CPU-heavy work, such as running a model locally, async doesn't help, and I would use processes or a separate worker instead.

```python
import asyncio
from openai import AsyncOpenAI

client = AsyncOpenAI()

async def get_completion(prompt: str) -> str:
    response = await client.chat.completions.create(
        model="gpt-5",
        messages=[{"role": "user", "content": prompt}],
    )
    return response.choices[0].message.content

async def process_multiple_prompts(prompts: list[str]) -> list[str]:
    tasks = [get_completion(prompt) for prompt in prompts]
    return await asyncio.gather(*tasks)

prompts = ["Explain Python lists", "Explain Python dicts", "Explain Python sets"]
results = asyncio.run(process_multiple_prompts(prompts))
```

## 40. What are Embeddings?

**Example answer:**

## 41. How Would You Build an AI Agent?

**Expectations:** LLM · Tools · Memory · Planning

**Example answer:**

> An AI agent uses an LLM to decide which actions to take to reach a goal, instead of answering in a single step. It has four main parts:
>
> - An **LLM** as the reasoning engine that reads the input and decides the next step.
> - **Tools**, such as web search, database queries, APIs, or code execution, that the agent can call.
> - **Memory**, both short-term conversation history and long-term knowledge, often in a vector store.
> - **Planning**, which breaks a complex task into smaller steps.
>
> The core is a loop: the LLM chooses a tool call, the application runs the tool, and the result goes back to the LLM until it can give a final answer. I would add guardrails such as a maximum number of steps, validation of tool arguments, and logging. Frameworks such as LangChain, LangGraph, or the OpenAI Agents SDK provide this loop, but it is also simple to write directly.

```text
User
 ↓
LLM
 ↓
Tool / Memory
 ↓
Result
 ↓
LLM
 ↓
Answer / Action
```

```python
def search_database(query: str) -> str:
    return f"Results for: {query}"

TOOLS = {"search_database": search_database}

def run_agent(task: str, max_steps: int = 5) -> str:
    messages = [{"role": "user", "content": task}]
    for _ in range(max_steps):
        step = llm_decide(messages, tools=TOOLS)  # a tool call or a final answer
        if step.final_answer:
            return step.final_answer
        result = TOOLS[step.tool_name](**step.arguments)
        messages.append({"role": "tool", "content": result})
    return "Stopped after reaching the step limit."
```
